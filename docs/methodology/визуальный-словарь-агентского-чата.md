# Визуальный словарь агентского чата

Этот файл нужен для клиентов, которые рисуют историю агента вне desktop SDK: iOS,
mobile-web, HistoryPanel, будущие оверлеи. Канон визуала уже существует в
`packages/claude-blocks/`, но это не означает, что его надо превращать в отдельную
публикуемую библиотеку для каждого клиента. Правильная модель: `claude-blocks` —
reference implementation, а потребитель зеркалит семантику, токены и иконографику
настолько близко, насколько позволяет его платформа.

Source of truth по слоям: `packages/claude-blocks/src/theme.css` — цвета,
типографика и статусные токены; `packages/claude-blocks/src/blocks.css` — форма
рядов, tool-карточек, thinking, diff, markdown; `packages/claude-blocks/src/icons/`
— inline SVG-геометрия и currentColor-подход; `ToolCard.tsx`, `ToolCards.tsx`,
`ThinkBlock.tsx`, `DiffView.tsx`, `ChatMessage.tsx` — эталонные решения по
конкретным типам строк. Подробная механика пакета и потребители описаны в
`docs/knowledge/fact-claude-blocks-package.md`.


Главное правило переноса: пользователь видит действие, не transport-name. Сырые
имена вроде `apply_patch`, `exec_command`, `write_stdin`, `mcp__server__tool` могут
жить в логах, debug detail или вторичном monospace-тексте, но не должны быть главным
лейблом строки. В transcript primary label должен отвечать на вопрос «что сделал
агент»: Bash/Run, Read, Edited/Edit, Write, MultiEdit, WebSearch, Grep/Glob, а не
название внутреннего вызова. Если новый клиент не знает tool-name, он показывает
generic tool-card, но всё равно не добавляет буквенный `MCP` как badge к thinking:
MCP — источник/категория tool-call, thinking — отдельный тип строки.

Статус tool-call несёт иконка, а не отдельная текстовая плашка. Running — spinner
в цвете акцента, done — зелёный icon state, error — красный, waiting/approval —
янтарный warning. Постоянный `done`-лейбл после успешного результата не нужен:
наличие результата + зелёная семантика уже говорят, что tool завершился. Для iOS
это значит: можно заменить SVG на SF Symbol, если платформа так естественнее, но
цветовая роль и место статуса остаются как в `ColoredToolIcon`.

Thinking — компактная строка с brain-иконкой и label `thinking`/`thinking · effort`,
с раскрытием тела под вертикальной rail-линией. Она не наследует tool-card MCP
форму, не получает `MCP`-badge и не становится generic tool row даже на мгновение
во время cold start, pending tool или SSE catch-up. Если клиент не может стабильно
приклеить thinking к хвосту истории, лучше временно оставить только header-loader,
чем рисовать ложный tool-block.

File-edit семейство всегда diff-first. Edit/Write/MultiEdit показывают path,
статистику добавленных/удалённых строк и раскрытое тело с `+/-` строками; для Write
все строки считаются добавленными. В collapsed preview первая строка отдаётся
пути/файлу и режется с начала, чтобы хвост имени оставался видимым; вторая строка
показывает `Added N lines, removed M lines` с зелёным added-count и красным
removed-count. `Edited` — title раскрытого блока/detail sheet, а не префикс compact
row: action-word съедает ширину и мешает понять, какой файл изменён. `apply_patch` в
чужом API — это не имя для пользователя, а один из транспортных способов получить тот
же edit-result, поэтому его нужно мапить в Edited/edit семантику и показывать
patch/diff, а не raw JSON.

Tool detail не начинается с `args/result` как пользовательского текста. Эти слова
допустимы только как внутренняя структура данных. В UI секции называются по смыслу:
Command/Output для shell, Patch/Result для edit, Input/Output для generic tool,
Content для read. Сначала payload приводится к читаемой структуре (команда, путь,
diff, pretty JSON, вывод), и только потом подсвечивается. Подсвечивать raw escaped
JSON значит красить шум вместо смысла.

Потребитель владеет скроллом, виртуализацией, персистом раскрытия, composer и
lifecycle процесса. Визуальный словарь владеет тем, как выглядит одна строка и её
состояния. Поэтому iOS не обязан импортировать React-пакет, но обязан сверять
нейминг, цвета, роли и статусные иконки с этим словарём перед добавлением новых
веток рендера.
