# Сценарии багов: карта кросс-фичевых связей

Граф пересечений фич Noted Terminal. Каждый узел = фича/подсистема, описывает что трогать вместе при изменении. Не пересказывает knowledge — даёт верхнеуровневый граф «трогаешь X — проверь Y и Z», конкретика в `knowledge/fact-*.md` / `fix-*.md` через ссылки.

**Как обновлять:** каждый раз когда обнаружился кросс-баг (изменил A → сломалось B), приходи сюда и добавь связь в оба узла. Не оставляй на «потом не забуду».

**Как читать:** перед изменением фичи открой этот файл, найди узел, прочитай «при изменении проверить» и «симптом рассинхрона». Узел даёт верхнеуровневую карту, дальше идёшь в `docs_search` за конкретикой.

Перед локальным фиксированием бага этого класса сначала восстанови модель состояний: что является источником правды, что только временным сигналом, а что проекцией для UI/API/кэша. Проверяй не happy path, а места, где слои могут разойтись: локальное/удалённое, UI/API/backend, кэш/source, очередь/result, interrupt/retry/restore. Если операция могла примениться частично или дважды, безопасное поведение — сохранить данные и честно показать расхождение, а не скрывать его как успех.

**Отличие от соседних файлов:** `сценарии-багов-design.md` — грабли вёрстки одного UI-компонента (popup-обрезка, hover-bridge, z-index). Этот файл — связи между **фичами** (изменил парсер → сломал resume). `knowledge/fix-*.md` — конкретный шрам подсистемы. Здесь только карта, не детали.

## Узлы

### JSONL parentUuid chain (центральный узел integrity)
Связан с: Timeline-парсер, HistoryPanel-парсер, Claude resume, EffortInject, kill-paths, CwdGuard, AutoRepair.
При изменении проверить:
- **два парсера должны иметь одинаковую recovery-логику**: `claude:get-timeline` И `claude:get-full-history` (Cmd+] панель) оба обходят parentUuid backtrace. Generic CHAIN BREAK recovery добавлен в один — обязан быть и во втором, иначе Timeline показывает полную историю, а HistoryPanel обрезает (или наоборот). Исторически HistoryPanel забыли — он обрезал когда Timeline был цел
- любой код который **пишет** в `~/.claude/projects/*/<sid>.jsonl` (наш или Claude CLI) — потенциальный источник phantom parentUuid и concatenated JSON lines
- compact passthrough: `compact_boundary` даёт dangling `logicalParentUuid` — recovery обязан перепрыгнуть на физического предшественника
- post-compact attachment init (MCP/skill reconnect пишет attachment с virtual parent в RAM, не на диск) — это **не** потеря данных, подавлять в парсере, не репортить как orphan
- JSONL user-запись может уже существовать, пока native Claude Rewind вернул этот prompt в редактируемое состояние. Это не orphan и не дубль для удаления: History/API должны оставлять запись, но помечать её live-статусом `editable-last-prompt` только по причинному сигналу успешного Rewind, а не по совпадению текста с composer.
Симптом рассинхрона: сессия открывается с фрагментом истории (4 сообщения вместо тысяч); Timeline и Cmd+] показывают разную длину; «Claude этого не помнит» граница не там.
Подробнее: `knowledge/fix-claude-2.1.x-phantom-parentuuid.md`, `fact-backtrace-jsonl.md`.

### EffortInject / ModelInject (startup defaults Claude)
Связан с: JSONL parentUuid chain, Claude resume, StatusBar model/effort defaults, Claude TUI settings dialogs, Claude CLI writer, bridge model update.
При изменении проверить:
- **не писать в JSONL пока Claude владеет файлом** — параллельная запись нашего `/effort` cleanup и Claude `last-prompt` metadata давала concatenated JSON без `\n` → phantom parentUuid. Это был **наш собственный** источник corruption, не баг Claude. Live `EffortCleanup` watcher удалён целиком; вместо него — trim хвоста только на restart (процесс мёртв, гонки нет)
- kill-switch: `effort=none` обязан отключать ВСЕ writers (и renderer-inject, и main-side cleanup) — defense-in-depth, conservative default (любой невалидный level = opt-out)
- **resume-guard разделён по сигналу**: при `claude --resume` Bridge/process-started путь НЕ инжектит `/effort` (там был paste-race), но `tui-ready` после отрисованного prompt'а может инжектить безопасно; once-per-process sentinel гасит дубль между ранним и fallback путём
- **startup settings chain упорядочена по подтверждённым событиям**: если задана default model, `/model <X>` идёт перед `/effort <Y>`, но `/effort` нельзя слать сразу после return из paste-функции. Completion barrier для модели — `claude:bridge-update` с matching model; completion barrier для effort — новый prompt boundary после submit (`prompt:<seq>`). Timeout в обоих местах — failure guard, не fallback для продолжения. Иначе `/effort` попадает в период `Switch model?` confirmation, а `/rewind` стартует до применения defaults.
- confirmation-menu proof проверяй не только по текущему PTY chunk: Ink может уже собрать `Switch model?` / `Change effort level?` в видимом terminal buffer, но нужные слова не совпадут в одном write. При регрессе «меню Yes видно, а `/resume` вернул 504 / Enter пришёл через 20 секунд» ищи assembled visible-buffer check, а не увеличивай timeout.
- timeout startup slash-command не означает «можно продолжить» и не должен оставлять команду в input. Если composer ровно равен ожидаемому `/model <X>` или `/effort <Y>`, допустим один Enter-retry; если после него exact command всё ещё лежит в composer, clear только этого текста и показывай failed overlay. Симптом рассинхрона: после restart в input торчит `/model haiku`, а UI не объясняет, отправилась команда или нет.
- prompt boundary markers живут по tab/xterm buffer, не по Claude process. `clearBridgeTab` не должен сбрасывать seq; иначе stopped-session Rewind после restart получает duplicate `prompt:1`, renderer его игнорирует и defaults gate висит.
- `Switch model?` и `Change effort level?` имеют похожие confirmation menus, но cooldown подтверждений не может быть per-tab: model-dialog и effort-dialog легально идут подряд. Ключуй cooldown по `tabId + dialogType`, иначе первое подтверждение подавит второе
- on-restart trim режет только **подряд** идущие `/model`/`/effort` startup slash-блоки в хвосте без ответа между; `/model → ответ Claude → /model` или `/effort → ответ Claude → /effort` обрезает только последний (у первого есть потомок)
- байты ≠ символы: `fs.truncateSync` работает в байтах, `String.indexOf('\n')` даёт индекс символа — на кириллице расходится, режет середину записи
Симптом рассинхрона: история показывает несколько `/model haiku` или `/effort max` подряд; обрезка сессии после смены model/effort; broken JSON line в хвосте (Cyrillic-сессии); Claude висит на `❯ 1. Yes, switch to Haiku`; после успешного model switch effort не вводится; ПКМ → Rewind на закрытой сессии запускает Claude и дальше «ничего».
Подробнее: `fact-claude-tui-control.md::Startup defaults /model + /effort`, `fact-claude-tui-control.md::EffortInject kill-switch`, `fix-claude-2.1.x-phantom-parentuuid.md`.

### Kill-paths и graceful exit
Связан с: JSONL parentUuid chain (flush), Stop button, close tab, app shutdown, build:install, safePasteAndSubmit mutex.
При изменении проверить:
- **graceful Ctrl+C через PTY (`\x03`) ПЕРЕД SIGTERM** во всех путях остановки: Stop button (poll до exit, max 300ms), close tab (busy turn: poll до exit, max 1200ms), shutdown (1200ms+1500ms deadline), PromptQueue Stop-after/Close-after. Это deadlines/fallback'и, не статические ожидания как источник истины. Close-tab wait привязан именно к `claudeTurnBusy===true`: на idle prompt один `Ctrl+C` лишь открывает danger-zone Claude и даёт чистый UI lag без flush-пользы
- close-tab warning и close-tab graceful-stop — разные gates. Warning нужен только при AI busy/streaming или обычном foreground process; `sessionId` сам по себе не блокирует close. Но live AI foreground всё равно должен пройти graceful stop перед PTY kill, даже если warning не показывался. Симптом рассинхрона: idle Claude/Codex с sessionId требует подтверждение, busy AI закрывается без warning, либо live AI закрывается мгновенным kill без `остановка сессии...`
- stop lifecycle имеет промежуточный `stopping`, а не прямой скачок `active/busy → inactive`. При изменении `terminal:stop-ai-process`, API snapshots или status-плашки проверяй desktop terminal, History, Timeline, Project API/SSE и iOS: send/resume/rewind/edit заблокированы, пока kill-ladder не дал финальный exit; desktop при этом сохраняет scroll/selection, а raw input/paste гасится в main. Симптом рассинхрона: нажал Stop, статус исчез, composer/Resume виден на пару секунд до реального завершения процесса или поздние клавиши попали в shell.
- API: `term.write('\x03')`, НЕ `term.ptyProcess.write` (IPty не имеет `.ptyProcess` — тихо падало 7 дней, валилось в SIGTERM)
- `before-quit` НЕ awaited Electron'ом без паттерна `event.preventDefault()` → async-работа → `app.quit()` + re-entry guard. Без этого приложение умирает до завершения graceful-поллинга
- `window-all-closed` не проходит через `before-quit`: не убивать там PTY/MCP напрямую, а сразу передавать управление в `app.quit()`. При правке shutdown/закрытия окна сверять пару `[Shutdown:before-quit] EARLY-MARK ai=N` → `AutoResume Starting N`; иначе после нового открытия вкладки останутся, а живой Codex не запустится. См. `fix-interrupted-session-lifecycle.md::Закрытие последнего окна обходило recovery`
- `build:install` через `pkill` обходит `before-quit` целиком (внешний SIGTERM минует Electron lifecycle) — нужен `osascript quit` через `graceful-quit.sh`
- AI-hop rebuild (`build_install_noted_terminal`) теперь НЕ мгновенный: Voice Record сначала ждёт idle всех сессий **кроме вызвавшей вкладки** через `/api/active-loaders`. При правке observe-логики проверь exclude-caller — вызвавшая вкладка busy сама по себе (запустила rebuild), без исключения ждёт вечно. См. `fact-build-when-idle.md::Observe-фаза`
- raw `\x03` write конфликтует с `safePasteAndSubmit` per-PTY mutex в редкой гонке — матчит существующий паттерн codebase, но при правке mutex проверь
- catch-блоки в kill-paths обязаны логировать (молчащий catch скрыл typo на неделю)
Симптом рассинхрона: «Press Ctrl-C again to exit» не появляется при Stop; сессия обрезается после закрытия вкладки/приложения; build:install корраптит активную сессию.
Подробнее: `fix-claude-busy-detection.md::Graceful Ctrl+C`.

### Dashboard Process Monitor
Связан с: Kill-paths, MCP multi-instance, Codex session lifecycle, Workspace Dashboard.
При изменении проверить:
- batch-kill Claude/Gemini/Codex должен убивать только truly external процессы; `!tabId` в текущем renderer не доказывает external, потому что процесс может принадлежать соседнему dev/prod instance
- MCP orphan count не должен включать MCP, чей parent chain приходит к любому живому custom-terminal main PID
- in-app stop идёт через lifecycle-aware путь (`terminal:kill`/соответствующий tab cleanup), а protected other-instance карточки видны без destructive hover/click
- Electron Dev stop не должен позволять убить текущий `process.pid` приложения
- process inventory не должен повторить старый sysmond-баг: один aggregate `ps` snapshot на refresh, видимый Dashboard only, медленный interval; новые колонки добавлять в aggregate builder, а не отдельным `system:get-*` polling IPC
- Dashboard project cards/process rows и titlebar `ProjectTabItem` — разные поверхности. При правке Home/Dashboard не менять геометрию верхних project tabs, если задача явно не про них; если diff всё же задел `ProjectTabItem`, проверить `project.icon`, высоту tab-chip и inline count-badge после названия.
- macOS Dock badge читает тот же busy-loader signal, что tab/project UI, но считает именно вкладки в loader-state, а не project process-count. При правке `busyTabs`/`pasteBusyTabs`, project badge или process-bar проверить Dock: count обновляется, count=0 сбрасывает icon, native red badge не возвращается, animation не включается обратно.
Симптом рассинхрона: крестик на Dashboard закрывает AI-процессы другого окна; orphan MCP count завышен; карточка исчезает с задержкой без loader; после stop остаётся фантомная вкладка; цифра process-count у titlebar project tab уезжает в правый верхний угол или пропадает иконка проекта; Dock показывает красный/top-right/stale badge или считает не loader-вкладки.
Подробнее: `knowledge/fact-ai-sessions.md`, `knowledge/fix-mcp-multi-instance.md`, `knowledge/fact-workspace.md`, `knowledge/fact-process-bar.md`.

### Terminal-слои и фоновый PTY
Связан с: Workspace project switch, mobile/API Terminal Control, History/Timeline, Terminal rendering.
При изменении проверить:
- визуальный фикс не unmount'ит, не убивает PTY и не переводит hidden tab в inactive: mobile/API/History должны продолжать send/resume/stop по скрытой вкладке
- активным painted terminal layer остаётся ровно один; inactive layers скрыты через `visibility:hidden` + `opacity:0` + `pointer-events:none`, а внутренний xterm наследует `visibility`
- project/tab switch, Dashboard/Home return и перенос окна между мониторами не оставляют старый `Process completed`/shell prompt в центре при уже обновлённых title/Timeline/status
Симптом рассинхрона: название вкладки, Timeline и ControlBar показывают новую сессию, но центральный терминал застрял на старой Codex/shell картинке; или после визуального фикса mobile перестаёт управлять скрытым терминалом.
Подробнее: `knowledge/fact-terminal-rendering.md`, `knowledge/fact-mobile-claude-pty.md`, `knowledge/fact-mobile-web.md`.

### CwdGuard / session detection (bridge)
Связан с: bridge session detection, JSONL parentUuid chain, tab persistence, resume.
При изменении проверить:
- CwdGuard защищает от takeover (чужая сессия перезапишет `terminalProjects`/`bridgeKnownSessions`), но **не должен блокировать `session-detected` → renderer**. Path drift (PTY cwd `/voice-record`, Claude cwd `/custom-terminal`) → blanket `return` → renderer не получил sessionId → таб потерял сессию после restart
- разделять: блокировать main-side кэши (takeover-векторы) — да; глушить renderer-side персист — нет
- два резолвера cwd расходятся: проверь оба пути
Симптом рассинхрона: вкладка теряет привязку к сессии после перезапуска; Stop button печатает `claude --resume` вместо остановки; сессия «пропала» из вкладки.
Подробнее: `fix-cwdguard-session-not-detected.md`, `fix-bridge-stale-takeover.md`.

### Codex session lifecycle
Связан с: Terminal command interception, Codex watcher, SQLite tab persistence, ControlBar, Timeline/HistoryPanel, Stop button.
При изменении проверить:
- `codex`, `codex-c`, `codex-f` должны выставлять `commandType='codex'` и `codexSessionId` так, чтобы Copy ID, Timeline, HistoryPanel и Continue появлялись без первого дополнительного turn'а
- при изменении Codex tool surface проверяй Timeline docs-атрибуты на обоих форматах rollout: прямые `apply_patch`/`docs_search` и orchestrated `exec` с реальным `tools.*(...)` вызовом внутри. Нельзя искать имена инструментов простым substring по source/output — `ALL_TOOLS`, `rg`, shell-команды и примеры строк дадут ложные зелёные точки. Симптом рассинхрона: `git status` подтверждает docs-правки и rollout содержит выполненный вложенный patch, но `docsEditedTurns=0`, либо точка зеленеет от одного поиска текста `apply_patch`.
- тот же сдвиг tool surface проверяется в HistoryPanel отдельно от Timeline: `exec` — transport, пользователь должен видеть вложенные Bash/Read/Edit/MCP-карточки из общего визуального пакета. Для async cell прямой `wait(cell_id)` завершает исходные карточки, а не добавляет второе служебное действие. Симптом рассинхрона: Timeline уже правильно ставит docs-точку, но History заполнена строками `EXEC const ...` / `WAIT N`, либо patch показан как JavaScript вместо diff по файлам.
- `codex-f` watcher не может полагаться только на cwd: если юзер выбрал директорию исходной сессии в Codex TUI, новый rollout-файл будет в другом cwd, и матч должен идти по `sourceSessionId` / `forked_from_id` внутри `session_meta`
- fresh `codex` watcher тоже не может принимать «последний rollout в той же папке»: root/user TUI session и subagent/`codex_exec` session — разные владельцы. При изменении session detection проверяй prod-класс 2026-06-25: новая вкладка без отправленного prompt не должна подхватывать subagent rollout другого Codex только потому, что совпал cwd. Симптом рассинхрона: вкладка показывает чужой loader/busy, Timeline привязан к prompt'у, которого пользователь в эту вкладку не отправлял
- запуск должен идти через `command codex ...`, иначе пользовательская zsh-функция/alias может добавить `--dangerously-bypass-approvals-and-sandbox` второй раз
- launch-параметры Codex (`--model`, `model_reasoning_effort`) должны сходиться через один helper и main-side SQLite fallback. При изменении StatusBar defaults или ControlBar per-tab state проверяй все entrypoints: Start/Continue/Fork, ручный ввод `codex`/`codex-c`/`codex-f`, pendingAction restore, AutoResume, Resume All, interrupted overlay. Симптом рассинхрона: StatusBar показывает Codex default model/effort, но часть запусков стартует со старой моделью или только ControlBar-кнопка передаёт args
- ControlBar Start/Continue должен передавать current `tab.cwd`, а не только project root. Если shell ушёл `cd ..` / `cd subdir`, rollout `session_meta.cwd` и watcher cwd могут расходиться, и вкладка остаётся без Timeline/copy-id при живом Codex
- fresh watcher обязан иметь related-cwd fallback (same-or-nested) после exact/source match: `session_meta.cwd=/parent`, launch cwd `/parent/child` — тот же рабочий контекст, а `/projA` vs `/projB` — чужая сессия
- startup confirmations Codex (`Update available`, `Do you trust the contents of this directory?`, directory chooser `Use session directory / Use current directory`) подтверждаются только по PTY-фрейму и one-shot guard'у. Update prompt выбирает `Skip`, trust prompt автоподтверждается только при выделенном `1. Yes, continue`; если меню не появилось, лишний `\r` станет пользовательским submit в composer. После chained prompt'ов проверяй не только raw PTY, но и quiet-snapshot xterm buffer (main/headless first, renderer fallback): raw может быть рваным после update, а экран уже дорисован
- desktop lifecycle status общий для Claude/Codex и не должен закрывать терминал визуально: компактная card стоит слева сверху и сдвигается ниже external-run badge, Start/resume не забирает focus, а интерактивен только собственный крестик. Stopping использует ту же card, но сохраняет safety contract в main: raw keyboard bytes отбрасываются, paste получает `agent_stopping`, пока kill-ladder не подтвердил exit; scroll/selection при этом доступны. Симптомы регресса: startup-автоматика через main `term.write` проходит меню, но ручные стрелки не работают; после статуса focus не возвращается; либо клавиши, набранные во время Stop, оказываются командой в shell
- новый rollout `codex-f` может несколько секунд расти за счёт копирования всей исходной истории; скопированные записи при этом могут иметь свежие внешние timestamps, поэтому append/время записи не являются live-proof. До настоящего composer-фрейма turn watcher держит fork history barrier, затем переносит offset на текущий EOF и только после этого считает новые rollout edges живыми. Проверяй большой fork со старыми `task_started/task_complete`: status не снимается от скопированного `task_complete`, busy не вспыхивает, main не читает сотни мегабайт append-дельт; видимый после уже залогированного auto-Skip кадр меню сам по себе не доказывает зависание автоматики
- Codex input-ready должен блокироваться на `Starting MCP servers ... esc to interrupt` и `MCP startup interrupted`. При изменении Rewind/History readiness проверяй stopped-session path: первый `Escape` не должен уходить в startup-interrupt до появления чистого composer'а
- Auth-меню первого запуска Codex (`Welcome to Codex`, `Sign in with ChatGPT`, `Device Code`, `API key`) — ручной блокер, а не startup prompt. При изменении startup/readiness проверяй, что приложение не нажимает Enter, не рестартит Codex watchdog'ом и не держит `Resuming`: runtime projection должен стать `inactive/manualActionRequired`, а внешний API должен быстро вернуть `codex_auth_required`
- `Starting MCP servers` — это не самостоятельный destructive-сигнал. Сначала классифицируй фазу: startup/resume до prompt'а или live turn после отправки prompt'а. Если уже есть `task_started`, pending paste audit, `CodexPromptInFlight` между PTY submit и первым rollout edge, queue handoff или ожидание matching `user_message`, watchdog не имеет права рестартить Codex: это tool-startup внутри пользовательского turn'а. Симптом регресса: отправка из History во время streaming сначала показывает ошибку, потом terminal session стирается/перезапускается
- Если `Starting MCP servers ... esc to interrupt` держится дольше watchdog-порога именно в startup/resume-фазе, recovery должен быть controlled restart из общего `codex:run-command` payload, а не Esc/ручной Continue и не отдельный iOS/API retry. Проверяй все entrypoints, которые запускают остановленный Codex перед действием: History Send, Timeline Rewind, Inbox/API run, AutoResume, interrupted overlay
- Hidden/background Codex readiness не должна требовать mounted renderer: main/headless xterm snapshot + clean raw PTY composer + живой Codex descendant process могут доказать ready, если renderer visible-buffer недоступен или stale. Но любой xterm snapshot, который показывает update/trust/directory/MCP blocker, сильнее raw-ready. Симптомы рассинхрона: hidden tab выходит из `starting` только после клика пользователя или, наоборот, Rewind/API начинают ввод в startup menu.
- При изменении Rewind, History Send, mobile/iOS params или Terminal API grep'ай прямые renderer proof calls (`terminalRegistry.getVisibleSnapshot`, `getCodexDraftState`, `waitForCodexDraftState`). Если path может стартовать из hidden tab/API/History, renderer-only чтение снова сломает background-flow; правильный источник — общий main/headless proof или явная ошибка, не отказ от фичи.
- Launch payload для MCP restart — per-launch retry-token, не persistent busy-state. Manual Stop, terminal kill, PTY exit и command-finished обязаны его чистить; watchdog internal stop сохраняет payload только с проверкой `launchId`. Симптом рассинхрона: пользователь остановил стартующий Codex, но watchdog всё равно перезапустил его или API продолжает отдавать `starting`.
- Manual Stop без найденного Codex PID тоже обязан закрыть общий `terminalCommandState` и отправить `command-finished`/`inactive`. `matches=0` означает что OS-процесса уже нет, но UI projection всё ещё может быть stale. Симптом рассинхрона: после Stop/возврата на вкладку снова крутится `Resuming Codex`, Continue подсвечивает вкладку как активную, но в терминале не вводится команда запуска.
- Delayed `D` с живыми Codex descendants должен проверяться до полного исчезновения процесса. Если guard заново эмитит `command-started` из-за `codex-descendant-alive`, у него обязан быть парный финализатор по process-tree `matches=0`; shell уже выдал `D` и второго события после смерти wrapper/vendor binary не будет. Симптом рассинхрона: пользователь нажал Ctrl+C/Stop, ушёл на другую вкладку, вернулся через минуты и снова видит `Resuming Codex` без новой команды в терминале.
- AutoResume после cold-launch не должен блокировать весь workspace ожиданием batch'а: старт — per-tab runtime state (`starting`, `inputReady`, `lastNotReady`) на Project API, desktop status и iOS. Один hidden Codex tab на `Starting MCP servers ...` держит только свой локальный статус, остальные вкладки запускаются независимо. Ранний `presence=inactive` сразу после `codex:run-command` не считается settled, пока не было `terminal:force-command-started`/runtime-start или явного failure. Симптом рассинхрона: после restart iOS/History показывает input для вкладки, которая ещё стартует, или один зависший таб держит весь экран.
- Desktop `Resuming Codex` status — tab-scoped state, а не свойство active tab. `codex:tui-ready`, `command-finished` и polling readiness обязаны скрывать плашку по tabId события, даже если пользователь ушёл на другую вкладку до готовности; `holdUntilReady` защищает только ранний `inactive` race после старта, но не `active`/`busy`/`manualActionRequired`. Симптом рассинхрона: Codex уже готов и input доступен, но при возврате на вкладку висит старый `Resuming` до ручного close.
- `/model` picker управляется по PTY-кадрам (echo/sync marker/menu title/selected row), не по фиксированным задержкам; ошибка picker'а обязана снять busy-overlay
- смена Model/Effort не должна делать raw `Ctrl+C`, пока renderer не классифицировал composer как `hasDraft=true`; на пустом prompt'е `Ctrl+C` закрывает Codex и следующий `/model` уходит в shell, а после отправленного `/model` draft восстанавливается через `ArrowUp` x2, потому что первый history item — сама slash-команда
- пустой Codex composer может содержать dim-placeholder, который выглядит как текст в буфере; draft-detector обязан смотреть cell-style (`dim`), а не hardcoded phrase и не `Ctrl+G` external-editor. Симптом: пустой input работает, но с текстом picker skip'ается или наоборот пустой input убивает Codex через Ctrl+C
- при изменении Codex input/send pipeline проверяй оба входа: `Cmd+]` History Send и Run after/PromptQueue. History сначала делает preflight/grab текущего composer'а, а Run after идёт через `codex:send-command` после auto-pop'а. Отдельно прогоняй multiline prompt, где первая строка composer пустая или начинается с отступа: detector должен вернуть `*:multiline-draft-row-N`, а не `unknown`. Симптом рассинхрона: History отправляет корректно, а Run after вставляет текст и не нажимает Enter, потому что post-paste guard ждёт hidden renderer или fresh render marker. Регрессия 2026-06-20: для Codex external submit нельзя возвращать post-paste UI/render ACK как pre-Enter gate; `skipRenderWait:true` здесь намеренный, а точный текст доказывается только rollout `user_message` audit после Enter.
- live picker в dev может ложно падать как `no-terminal`, если HMR сбросил module-scope registry xterm refs; registry должен переживать hot reload через process-wide singleton, иначе отладка picker'а идёт по ложному следу
- Cmd+] History controls для Codex должны идти через отдельный runtime/adaptor, а не через Claude-only ветки: при изменении HistoryPanel проверяй, что справа есть Codex textarea, Resume/Stop/Pull/Send/Interrupt, и что `Workspace.enableClaudePtyControls` пропускает `toolType='codex'`. Симптом рассинхрона: History открывается, но справа только список сообщений без input/stop/resume
- History send preflight для Codex обязан сначала классифицировать xterm composer (`dim-hint` = пусто) и только при реальном draft вызывать `codex:grab-input`. Нельзя использовать Ctrl+G как пустую диагностику: external-editor cycle может изменить composer и проглотить следующий `codex:send-command`
- Range popup в Timeline не должен быть Claude-only: `Копировать` работает для Codex через rollout, `Редактировать` — через `codex:edit-range`, `Удалить выбранное` — через `codex:delete-range`; обе мутации создают локальный rollout fork. Token estimate/breakdown остаются Claude-only. При изменении multi-select/History actions проверяй Codex middle-history edit и delete отдельно от Claude compact-boundary rules: выбор через один или несколько compact обязан удалить ровно selection, правая зона split-кнопки — только явный префикс. На большом rollout проверяй порционную запись, exclusive-create и cleanup недописанной копии: mutation не должна собирать ещё одну полную строку размером со всю историю или оставлять resumable partial JSONL. Отдельно прогоняй public `/api/terminal-tabs/:tabId/edit-range` и `/delete-range`: API требует inactive tab, adopt'ит `newSessionId`, а stop/resume делает вызывающий сценарий. Симптом рассинхрона: desktop Timeline работает, но внешний API отвечает Claude-only/active-conflict не тем статусом, не обновляет tab session id, или следующий `/resume` открывает старый rollout.
- Codex обычный Rewind пересекает Timeline target selection, PTY transcript overlay, duplicate accounting, rollout rollback и History refresh. Перед `Enter` должен быть доказан selected/current overlay text; если нет — закрыть overlay через `q`, не `Escape`, и не менять History state. Первый PTY chunk после `Escape`/стрелки не считается готовым кадром: жди stable highlighted row, `›` не proof, а row-order рядом с target даёт только one-step correction с повторным style-proof. После успешного `thread_rolled_back` UI держит `REWINDING`/`Updating history...` до refresh `codex:get-full-history`, иначе пользователь видит «откат закончился», а старые rows исчезают только через долю секунды. Симптом рассинхрона: пользователь выбирает Rewind, overlay Codex открылся и «завис», rollback ушёл не в тот prompt без понятного лога, либо marker пропал раньше чем JSONL-история догнала откат.
- Startup-like frame внутри Codex Rewind confirm (`Update available`, chooser, MCP text) не равен startup-state, пока Rewind ещё может восстановиться через grab. При изменении confirm/grab path проверь логовую цепочку: `confirm exposed startup-like frame` не должен слать SSE `starting`; `status=starting` допустим только если последующий grab/failure не восстановил composer. Симптом рассинхрона: iOS/desktop на секунду показывает `starting`, хотя Rewind успешно переносит prompt и возвращает `active`.
- Codex AI Rewind пересекает Timeline/History, Gemini compact, `safePasteAndSubmit` и rollout watcher. При изменении Rewind/History send проверяй `codex-rewind-ai` audit: ближайший `event_msg.user_message` должен совпасть с Gemini result по длине/hash. Симптом рассинхрона: UI показывает что AI Rewind отправлен, но Codex prompt или JSONL начинается с середины/хвоста сводки (например сразу с пунктов 4-5 списка).
- Codex busy/ready в History, ControlBar и PromptQueue должен идти от `task_started/task_complete/turn_aborted`, а не от `send-click`, `PasteBusy` или raw Ctrl+C. При interrupt `Ctrl+C` не ставь `READY` до `turn_aborted`; при clean send не ставь долгий `BUSY` до `task_started`
- При аудите похожих регрессий ищи не только конкретную строку MCP, а весь класс «текст терминала стал управляющим состоянием»: `>`/`⏵`, `›`, raw PTY tail, visible-buffer tail, blocker-фразы update/trust/cwd. Любой такой detector должен доказывать current frame + phase + session/launch freshness + отсутствие in-flight turn/paste audit. Если есть только риск по коду без логов, сначала добавь логи (`source`, `readyAgeMs`, current session, busy/turn state, blocker, preview), а не меняй алгоритм на догадке.
- Общий API-сценарный слой (`/api/terminal-tabs/:tabId/*` и `/api/inbox/runs`) надо проверять как отдельный entrypoint, а не считать его thin-wrapper'ом над terminal primitives. Обязательная матрица: send на idle, send во время streaming/queue, soft interrupt с возвратом draft из TUI, hard stop, stopped-session rewind, AskUserQuestion answer/stop. Симптом рассинхрона: History работает, но iOS/API показывает только "loading", теряет restored draft или делает rewind до готовности TUI.
- Project API и Inbox API используют один scenario layer, но разный ownership composer'а. Если меняешь preflight или draft recovery, проверь что `/api/terminal-tabs/:tabId/send` оставляет TUI draft на месте, а `/api/inbox/runs` возвращает draft наружу и очищает TUI. Общее место кода не должно стирать это различие статусов.
- Native iOS send не должен использовать `GET /draft` как обязательный preflight перед обычной отправкой. `/draft` — это authoritative grab после interrupt/Rewind или явного pull, а не "можно ли нажать Send". При изменении preflight проверяй логовую цепочку: idle Send идёт в `/send`, busy Send идёт в очередь, а ложный `claude_busy` не оставляет текст в input без отправки.
- В transcript UI `thinking` не наследует форму pending tool-row. Если pending tool-use ещё без результата, клиент либо скрывает его, либо ждёт completed tool row; он не рисует `MCP thinking` с badge/chevron. Симптом рассинхрона: после Send или сразу после завершения turn на мгновение появляется раскрываемая строка `MCP thinking`, хотя пользователь должен видеть только статус размышления.
- External `/api/inbox/runs` — ещё один launch/send/stop entrypoint Codex. При изменении Codex startup, profile args, watcher, busy-state или stop-flow проверяй внешний run отдельно: readiness должна идти по `agent:tui-ready-internal` + `inputReady`, `conversationKey` должен переиспользовать tab/session, а auto-stop не должен стартовать до SSE `done`. Симптом рассинхрона: Voice Record или другой внешний чат висит «генерирует», хотя Codex уже ответил в терминале; либо следующий prompt создаёт новый Inbox tab вместо продолжения прежнего.
- Для внешних клиентов `done` — авторитетный terminal event. `busy:false` без `done` не завершает run, а ошибка scheduling metadata/auto-stop не должна блокировать отправку `done` подписчикам. Симптом рассинхрона: ответ виден в Noted Terminal, но внешний чат не сохраняет assistant-message и остаётся со spinner'ом.
- Draft conflict надо проверять в двух endpoint'ах, потому что ownership разный: `/api/terminal-tabs/:tabId/send` возвращает `409 terminal_draft_conflict` и оставляет текст в TUI, а `/api/inbox/runs` возвращает `draftText + originalPrompt`, очищает TUI и ждёт rollback во внешнем composer'е. Симптом рассинхрона: iOS-отправка стирает текст из терминала; или Voice Record показывает error bubble/ghost user-turn вместо возврата текста в input.
- Первый Inbox-run проверяй отдельно от повторного: paste audit может начаться до появления turn-watcher'а, поэтому session detection обязана поднять watcher с pending-audit catch-up и доказать ближайший `event_msg.user_message`. Симптом рассинхрона: первый Codex prompt через Voice Record виден и отвечен в терминале, но API падает `codex_turn_watcher_unavailable` или не присылает `done`; второй prompt в той же вкладке уже работает.
- Build-install callback через Voice Record — третий внешний prompt entrypoint Codex, не просто "после билда написать строку". При изменении `/terminal/ai-prompt`, Codex startup prompts или audit-status проверь, что callback отправляет completion prompt **ровно один раз**: `sent_unverified`/timeout после handoff'а не должны запускать повтор. Симптом рассинхрона: после install в tab спамится несколько одинаковых `Build install completed...`, особенно если на старте Codex показал `Update available` или directory chooser.
- Для Codex audit отдельно проверяй prompt с ведущими пробелами и same-prefix targets: rollout `user_message` может быть canonicalized без leading whitespace. Это не должно давать ложный `codex_user_message_audit_mismatch`, но mismatch середины/хвоста по-прежнему должен падать fail-closed.
- History interrupt-recovery для Codex должен слушать `turn_aborted`, а не только Claude-style `interrupt`. После быстрого Stop terminal composer может восстановить prompt чуть позже JSONL-события, поэтому проверяй delayed probe terminal draft; fallback на last sent prompt запрещён. Симптомы рассинхрона двусторонние: текст вернулся в terminal input, но textarea History осталась пустой; textarea History показывает prompt после Stop, хотя terminal input его не вернул
- Stop ищет прямого child-процесса `codex` через `terminal:stop-ai-process`; Ctrl+C/повторный ввод `codex` не является stop-flow
- foreground classification для close/warning должна читать full command-line, не только `comm`: direct child Codex часто выглядит как `node /opt/homebrew/bin/codex` или `@openai/codex`, а обычный Node/npm внутри AI-typed tab должен остаться обычным процессом с warning
- `⎘ prompt | + clear` должен ставить external-editor lock на vendor Codex PID, а не только на wrapper PID; иначе Ctrl+G уходит в обычный редактор и ничего не копирует
- запуск, остановленный до первого rollout/session id, должен откатить auto-name/auto-color и не показывать Continue
- не переносить Claude bridge/pendingResume/CwdGuard слой на Codex без реального симптома: у Codex нет stale `~/.claude/bridge/*.json`, источник истины — rollout JSONL в `~/.codex/sessions/`; общий риск только в hard-kill до flush'а, поэтому важнее graceful-stop и игнор битого JSONL-хвоста
Симптом рассинхрона: Codex запущен, но Timeline и copy-id пустые; после Stop нет Continue; Codex-F открыл правильный диалог, но вкладка его не подхватила; `/model` уходит новой строкой или падает с ошибкой; при смене модели input очищается, picker не открывается, через несколько секунд draft возвращается; обычный Rewind открыл transcript overlay и застрял без rollback; loader правого кластера залип; `⎘ prompt` открывает Sublime/редактор вместо копирования; пустой запуск оставляет зелёную/AI-вкладку и Continue на несуществующую сессию.

### Tab naming / AI launch metadata
Связан с: TabBar inline rename, AI launch snapshots, Claude/Codex session detection, Settings built-in prompts, SQLite tab/history persistence.
При изменении проверить:
- fresh `tab-N` в режиме inline rename → клик Claude/Codex launch без изменения текста → первый real user prompt обязан сгенерировать AI-название; unchanged blur/Enter не должен ставить `nameSetManually`
- ручная правка имени до launch блокирует auto-title, а ПКМ `Обновить название` остаётся явным override с loader'ом
- Settings → AI prompt display name можно менять свободно: runtime привязан к stable id `tab-title`, не к названию строки
- Codex bootstrap `# AGENTS.md instructions for ...` / `# GEMINI.md instructions for ...` не eligible для auto-title, даже если upstream пометил блок как `role=user`; название должно идти от первого реального `event_msg.user_message`
- fork Claude/Codex из текущей сессии или clipboard source → copied parent entries игнорируются, новое название берётся из первого eligible prompt после fork boundary; для Codex с известным source session проверяй line-boundary, не свободный timestamp fallback
- fresh-start surfaces проверяются списком, а не по одной кнопке: ControlBar Start, typed-intercept в Terminal, `pendingAction` `claude-new`/`codex-new`, external `createAgentTab(startNow=true)`, History runtime fresh-start и no-session InfoPanel chip. Все они должны взводить `markAiLaunchAutoTitle`; resume/continue/edit-range не должны
- свежий session id может первым прийти не из профильного detector'а, а из общего MCP/runtime-сигнала; auto-title должен армиться по launch snapshot/intent при первом materialized session id, а не по конкретному `reason`, иначе Timeline увидит первый prompt без pending и вкладка останется `codex`/`claude`
- auto-title failure path проверяется как цепочка, а не как один guard: есть `arm` → есть `candidate` → generator вернул title/fallback → только потом `consume`. Если `consume` происходит до результата generator'а, transient API/Gemini failure превращает временную ошибку в потерянный retry
- restore, Cmd+Shift+T, обычный resume и повторное чтение Timeline не армят auto-title заново, но сохраняют manual ownership из tab/history
Симптом рассинхрона: свежая Claude/Codex вкладка остаётся `tab-1`/`tab-2` после первого prompt'а, хотя session id есть и ручной `Обновить название` работает; fork-tab наследует старое имя/старый первый prompt вместо первого prompt после fork; либо переименование prompt'а в Settings неожиданно ломает auto-title.
Подробнее: `knowledge/fact-tabs.md`, `knowledge/fact-settings.md`, `methodology/сценарии-использования.md::Edge: первый prompt задаёт название вкладки`.

### Prompt Queue / local-command boundaries
Связан с: Run after runner, Claude busy-state reason, `/compact` local-command watcher, workspace restore/hydrate, Settings Run after fonts, mobile-web mirror.
При изменении проверить:
- `spinner` и обычный `local-command` не fire/disarm очередь; successful `/compact` — исключение и продолжает очередь после durable compact marker (`compact_boundary` / summary / stdout)
- `reason:'spinner'` не должен даже переписывать workflow busy-snapshot, а hook `UserPromptSubmit` / `Stop` / `StopFailure` обязан дойти до runner независимо от совпадения boolean с последним visual frame. Иначе настоящий Stop после spinner-idle теряется как дубль
- Escape/error/abort target-tab отменяет не только его собственную очередь, но и все активные cross-project owner-очереди с `runAfterTabId === target`; items сохраняются, auto/stop/close/countdown и одноразовый target очищаются
- active-count, first-chip hint, manual empty-out и runner head берут только `enabled !== false`; legacy items без поля `enabled` считаются enabled
- right-click card menu и mobile checkbox меняют один и тот же `QueuedPrompt.enabled`, а не заводят второй mobile/filter-state
- target chain-drain остаётся сильнее pivot fan-out: если trigger-tab сам имеет runnable Run after, owner ждёт весь drain trigger-таба
- restore/hydrate guard: пока `useWorkspaceStore.isRestoring` или `openProjects` ещё пустой, runner не должен чистить queues закрытых owner/target и store не должен сохранять пустой snapshot поверх hydrated SQLite. Быстрое действие до ответа SQLite должно merge'иться с persisted items/настройками, а не включать старый `next.has(tabId) → skip`, который затирал всю сохранённую очередь вкладки
- очередь с вложениями обязана владеть **самими байтами**, а не ссылкой на cache/temp другого runtime. При `+Grab/+Add` Claude/Codex source копируется в `userData/prompt-queue-assets`, item хранит content-addressed `assetId`, hydrate мигрирует legacy path, а Replay/Run after повторно валидируют файл до передачи ownership. Нельзя считать восстановленный `📎N` доказательством, что файл существует; missing item остаётся в очереди и disarm'ит автоматику. Симптом рассинхрона: после restart карточка и счётчик есть, но агент получает stale path, а chip исчезает как будто отправка успешна.
- durable macOS path из `Application Support` нельзя писать в Codex composer напрямую: пробел ломает path detection и вместо native `[Image #N]` остаётся буквальный путь. Live paste, Replay и Run after обязаны передавать один и тот же whitespace-free transport alias, сохраняя binding на durable asset. Alias изображения идёт отдельным paste event от соседнего текста: Codex распознаёт path только когда весь payload события является одним путём. Проверяй image-only, image+text, text+image+text и несколько interleaved image; 4K-файл не должен копироваться в alias второй раз.
- Codex image placeholder нельзя связывать с «последними N path»: после удаления или перестановки slot'ов это тихо подменяет изображение. Stage token + PTY redraw связывают конкретный asset с `[Image #N]`; fallback разрешён только при exact-count, неоднозначность становится visible missing-state. Raw `Ctrl+C` активного turn не очищает binding, потому что queued draft остаётся в composer; Enter-submit/Grab/new launch/teardown очищают. Минимальные сценарии: A/B→удалить B→Grab должен вернуть A; A/B→переставить `#2,#1` должен вернуть B/A; Grab до redraw с равным count должен восстановиться; A/B→interrupt current turn→Grab возвращает A/B; count mismatch не угадывает.
- editor очереди считает image marker валидным только при точном неэкранированном `[Image #N]` и известном asset: валидный marker синий, обрезанный/экранированный/с неизвестным номером теряет цвет, сохраняет refs и блокирует Replay/Run after. Полное удаление marker'а, наоборот, осознанно освобождает только этот ref. Проверяй повреждение обеих скобок, `\[Image #1]`, замену номера и удаление одного marker'а при двух изображениях.
- Restart after terminal/dev-вкладки слушает те же busy edges, но делает другой side effect: stop/restart или выбранный script в целевой вкладке. При изменении Run after picker, busy-state reasons или script launch проверяй, что `spinner`/interrupt/error не запускают restart, а natural Codex `task_complete` / Claude/Gemini idle запускают
- Restart after + конечный script должен быть single-flight: если trigger-tab завершился ещё раз, пока предыдущий script целевой вкладки выполняется, не stop'ь текущий script и не запускай второй экземпляр; ставь один pending rerun до `terminal:command-finished`. Если за это время target поставили на pause, pending обязан сброситься без запуска. `dev`/`start`/`serve`/`watch` остаются controlled restart, потому что сами могут не завершиться.
- Replay/Run after submit не имеет renderer-side raw Enter fallback. При изменении replay, append-input или dev-HMR путей проверяй: `submitted:false` сохраняет chip, а `submitted:true` атомарно удаляет chip и одноразовый target даже при позднем audit timeout; Codex visual guard и Claude `UserPromptSubmit` audit нельзя обходить `terminal:input '\r'`. Симптомы рассинхрона: текст вставился, но не отправился — ошибка main guard'а/аудита; turn уже стартовал, а chip остался — ownership ошибочно привязали к позднему аудиту
- Restart after self-target должен сбрасываться в null не только в picker UI, но и в store/API слое. Симптом рассинхрона: фиолетовый restart-marker есть, но вкладка ждёт саму себя и никогда не перезапускается
- Restart after теперь multi-trigger: новый source of truth — список `restartAfterTabIds`, legacy `restartAfterTabId` только mirror первого trigger'а. Любой consume/build-idle guard, который проверяет только старое поле, пропустит часть подписок или неправильно решит, что подписки нет.
- Restart after не должен зависеть от legacy `restartAfterArmed` / `restartAfterPersistent`: выбранный trigger-list уже является активной подпиской, кроме явного `restartAfterPaused === true`. Симптом рассинхрона — в ПКМ видно выбранную AI-вкладку и `npm run dev`, trigger loader штатно завершился, но target не перезапустился, потому что старый guard ждал bell-флаг; обратный симптом — paused UI серый, но completion всё равно запускает side effect или `/api/active-loaders` ждёт paused restart-after command.
Симптом рассинхрона: после Escape/error внешняя очередь всё равно стреляет; после успешной отправки item и выбранная `on tab` остаются в панели; после `/compact` loader гаснет, Run after остаётся armed, но следующий prompt не отправляется; после build-install/рестарта один-два чипа исчезают и `promptQueueByTab` становится `{}`; mobile показывает `[N]` отличный от desktop; выключенная карточка либо исчезает из списка, либо всё равно уходит в Claude.
Подробнее: `knowledge/fact-prompt-queue.md`, `knowledge/fact-mobile-web.md`.

### SDK type-ahead mid-stream очередь
Связан с: SDK channel (AsyncIterable), chip promotion, assistant-ui MessageRepository, Anthropic JSONL persistence, mobile-web mirror.

Симптом рассинхрона: deadlock (сообщение не доставилось); assistant-ui «Something went wrong»; QUEUED chip висит над инпутом после ответа Claude; на мобилке очередь рендерится иначе.

### Timeline ↔ HistoryPanel парность
Связан с: JSONL parentUuid chain, toast (effectiveTabId), Claude memory boundary.
При изменении проверить:
- любая recovery/boundary-логика в Timeline дублируется в HistoryPanel (Cmd+]) — это два независимых рендерера одних JSONL-данных, легко обновить один и забыть второй
- добавление нового engine'а в Timeline требует парного `get-full-history` канала и явных gates для Claude-only действий (`Edit Range`, fork marker, token breakdown); иначе Timeline покажет точки, а Cmd+] или context-menu останутся в старой семантике
- HistoryPanel controls — это не только рендер истории, но и оболочка live TUI input. Send из `Cmd+]` обязан делать preflight terminal draft: если draft есть, перенести его в начало textarea, показать warning и остановить отправку. Иначе ручной текст из терминала склеится с новым prompt'ом и уйдёт как один запрос
- Claude History parser не должен удалять queued user-visible ввод на `queue-operation remove`: в AskUserQuestion flow `remove` может быть единственным следом prompt'а (`стоп`) без последующей `type:user` записи. Симптом рассинхрона: терминал показывает `стоп` между ответом на вопрос и финальным Claude-сообщением, а History либо теряет его, либо оставляет вечный spinner.
- ручной Pull terminal draft при пустом TUI input — no-op, не warning. Он может показать короткое нейтральное `Terminal input empty`, но не `Send stopped · draft moved`; иначе юзер думает что отправка была остановлена, хотя ничего не переносилось
- Claude native Rewind пересекает Timeline target, `/rewind` picker commit-position и History textarea. При изменении Rewind тестируй соседние prompts с одинаковым префиксом (две строки начинаются с `"Это ..."`) и историю где picker забит slash-command строками (`/model haiku` + `/effort low|max`) при маленькой высоте терминала. Обязательный сложный сценарий: несколько user-сообщений, потом 3-5 подряд model/effort slash-команд, потом ещё сообщения, manual Stop/Continue и Rewind из середины через API/History. Успех доказывается parentUuid следующего prompt'а относительно target и post-grab full-text match; подсвеченная строка в picker сама по себе не доказательство.
- Результат Claude native Rewind (`historyPromptDraft` + локальный `I REWOUND` preview) должен писаться в tab-scoped UIStore, а не только через `history-panel:rewind-log` listener внутри mounted HistoryPanel. Иначе Rewind при закрытой History успешно переносит prompt из terminal composer, но при последующем открытии Cmd+] панель показывает полный transcript без preview/draft, потому что событие потерялось пока панель была unmounted.
- HistoryPanel не должен оборачивать целые transcript entries в общий full-width collapse control (`Раскрыть полностью`/`Свернуть`). Схлопывание допустимо только на конкретных подблоках (compact summary, tool/card details, явно спроектированный prompt preview). Whole-entry wrapper вставляет огромные полосы между сообщениями и прячет actions/thinking вне визуального контракта History.
- Claude picker имеет два доказанных commit-frame: старый `targetBeforeSelected=true` и новый `› <target>` / style-selected row (`selectedMatchesTarget=true`). Parser должен сохранять raw marker до normalize; `›`/`❯` в picker не равны composer readiness. После стрелки первый RGB/marker PTY chunk не считается полным кадром — нужен quiet-drain/stable snapshot перед проверкой. Тестируй Rewind в visible tab и в background/stopped tab: renderer-only snapshot снова даст симптом «запустил Claude и дальше ничего».
- `targetBeforeSelected=true` запрещён как proof, если selected row — slash-command (`/model`, `/effort`) или control row. В таком кадре Enter коммитит selected command, а не target above; симптом — Rewind восстанавливает `/model haiku` вместо выбранного сообщения и падает только на post-grab mismatch.
- Codex native Rewind имеет отдельный proof edge: active prompt доказывается xterm cell-style, но одноходовый/multiline prompt через API/History может дать active snapshot только первой visual row. При изменении Codex Rewind тестируй single-entry session с multiline target: длинный active visible prefix полного target допустим, короткий/общий prefix не proof. Симптом рассинхрона — `codex_rewind_target_not_selected_before_enter` при единственной подсвеченной target-строке или, хуже, rollback на prompt с тем же началом.
- Codex compact markers проходят через тот же rollback-projection слой, что user-turn'ы: `thread_rolled_back` оставляет строки в rollout, но `codex:get-timeline` и `codex:get-full-history` должны вернуть один и тот же набор compact uuid текущей ветки. Симптом рассинхрона: после Rewind HistoryPanel уже усечена, а Timeline показывает несколько оранжевых compact markers подряд из сырого хвоста.
- Rewind из остановленного Claude отдельно проверяет launch/defaults gate: кнопка активна при inactive process, но `/rewind` не отправляется пока `/model`/`/effort` не подтверждены и prompt boundary не пришёл. После `/rewind` Enter отдельно доказывай, что открыт picker, а не slash-help (`slashHelpOpen=true && menuLooksOpen=false` → один confirm Enter, потом снова proof). Симптом рассинхрона: ПКМ → Rewind запускает Claude и дальше «ничего», либо `/rewind` появляется до `/effort`, либо строка `/rewind Restore the code...` остаётся в slash-help.
- Rewind/Send/Edit запрещены на runtime `stopping` для Claude и Codex. Это не `busy` и не `inactive`: процесс уже teardown'ится, но ещё может держать TUI/rollout/watcher. Симптом рассинхрона: History или iOS успевает начать Rewind/Send после Stop и получает input mismatch, пропущенный draft или stale status.
- History textarea draft живёт по tabId, не по mount'у панели. Закрыть/открыть `Cmd+]` не должно чистить input; clear только после успешного send или явного действия
- Transcript freshness для Timeline, Cmd+] HistoryPanel и Project API/iOS идёт через общий `SessionTranscriptService`, не через отдельные intervals в каждом renderer/client. При изменении parser/cache/refresh проверяй все три поверхности на одной большой Claude/Codex-сессии. Симптом рассинхрона: Timeline показывает новую точку, History stale до ручного reopen, или iOS видит историю только после выхода/входа.
- Semantic group header и compact cluster — только display projection: любая навигация, Rewind, note и range-action продолжают адресовать raw UUID. При compact-normalization проверяй Timeline, History, Copy/export и rollback вместе: одна пара `compacted/context_compacted` не должна стать двумя сжатиями или остаться видимой после collapse владеющей группы.
- Один watcher/invalidation service не защищает от consumer-storm: Timeline, History и presence держат one-flight + максимум одну trailing reconciliation. Новый detail/hover consumer не имеет права запрашивать eager full History ради одной карточки. Тестируй metadata discovery, Timeline и full History на одной большой сессии; симптомы — пустая Timeline несколько секунд, рост памяти от одного hover/open или несколько одинаковых full-history IPC одновременно.
- Live SSE и canonical `/history` должны классифицировать строки одинаково. Если live показывает startup `/model`/`/effort`, `thinking` или raw `tool_result`, а reload сразу удаляет это, значит Project API снова отдаёт raw-событие без display projection. При изменении queued/slash/parser paths проверяй: обычный queued prompt остаётся History+Timeline, startup slash виден в History как `/model haiku` / `/effort low` (не `/modelHaiku`), но не materialize conversation и не становится Timeline turn'ом; thinking не становится durable row. Manual/API/startup source не меняет display, если durable-запись одна и та же.
- toast про chain-break: tab-scoped через `effectiveTabId`, baseline policy (первая загрузка молчит, тост только на рост) — иначе спам тостов на каждой вкладке при rebuild
- `isChainBreakZone` (красная зона «Claude не помнит») — единый канал, не плодить параллельный ghost-channel поверх существующего `isOldHistory`
Симптом рассинхрона: Cmd+] обрезает а Timeline целый; тосты спамятся на всех вкладках; две разных подсветки границы памяти; History send подхватывает лишний текст из терминального composer'а; prompt после Stop вернулся в терминал, но не в History input; закрытие панели стирает недоотправленный prompt; пустой pull показывает ложный warning об остановленной отправке.
Подробнее: `fact-timeline.md`, `fact-backtrace-jsonl.md`.

### Project Home ↔ Semantic Search ↔ main loop
Связан с: ProjectHome mount, SemanticSearchSection, SQLite schema/indexes, main-process IPC wrapper.
При изменении проверить:
- `SemanticSearchSection` вызывает `search:stats` при обычном открытии Home, а не только при поиске. Любая правка `session_chunks` schema/indexes или `getIndexStats()` должна проверяться через Home click/hover, `[Perf:IpcSlow] channel=search:stats` и query plan `COUNT WHERE embedding IS NOT NULL`
- если Home зависает, не обвинять `HomeCommit`, `HomeStatusSync` или Timeline без пересечения по логам: `ipcAgg5s=search:stats` уже был root cause 4s main-loop freeze
- partial index `idx_chunks_embedding_present` — responsiveness invariant, не search-quality оптимизация
Симптом рассинхрона: пользователь нажимает Home, экран уже виден, но hover/click всего приложения замирает на 2-4 секунды; повторные переходы могут быть быстрее из-за прогрева.
Подробнее: `knowledge/fact-project-home.md`, `knowledge/fact-semantic-search.md`, `knowledge/fix-performance-lags.md`.

### Toolbar usage chips ↔ main loop
Связан с: ProjectToolbar, Claude/Codex usage chips, Codex `logs_2.sqlite`, main-process IPC wrapper.
При изменении проверить:
- Codex usage refresh не должен ждать полный account-log scan в foreground. Если `logs_2.sqlite` scan медленный, toolbar продолжает показывать last-known local cache; сам scan не поднимает `updating` и после failure уходит в cooldown.
- Force-refresh кнопка в usage popover'е не должна блокировать весь toolbar/main loop и не должна менять tab lifecycle (`starting/resuming/active`). Usage — account-level status, не runtime-state вкладки.
- Current Codex account refresh идёт через `/backend-api/wham/usage`; local scan только discovery/fallback и не управляет spinner. HTTP обязан иметь physical abort/deadline, IPC — внешний deadline, а renderer не должен polling'овать `refreshing` коротким таймером.
- Успешный HTTP 200 не равен verified snapshot: тот же account может кратко флапнуть с обычного used на почти нулевой и обратно. Подозрительный reset/regression держит last verified до второго совпавшего ответа через минимум 30s или до фактического наступления старого reset; force refresh не обходит проверку.
- Verified snapshots максимум восьми маскированных аккаунтов переживают рестарт через `app_state`; проверяй, что persisted payload не содержит token, auth fingerprint, полный email/account id. Historical OpenAI snapshot после restart остаётся stale, но сам по себе не запускает local scan.
- Healthy server response не должен ждать `loadSessionRecords`: active rollout enrichment только fallback и читает bounded tail, потому что один rollout может занимать сотни MB.
- Success и error применяются только если account key + auth fingerprint не сменились. Известный mismatch аккаунтов всегда запрещает active rollout overwrite; `sourceThreadId` fallback допустим только при неизвестной identity.
- Нельзя приписывать unknown thread identity текущему глобальному auth по timestamp: старая сессия аккаунта A может продолжать писать после login в B.
- Null/partial/unknown окна не превращаются в `0% left` и не подписываются по позиции `primary/secondary`: 5h/weekly определяются по длительности окна. На failure последнее значение остаётся с source/timestamp/stale.
- В account switcher зелёная точка принадлежит только текущему Codex login; historical accounts серые даже когда выбраны. Длина полосы равна remaining, цвет полосы/текста отражает used-urgency.
- При расследовании лагов grep'ай `[Perf:IpcSlow] channel=codex:get-usage`, `[CodexData] remote usage ...`, `[CodexData] usage accounts refresh ...`, `source/stale/account`, а не только React render toolbar'а.
Симптом рассинхрона: пользователь открывает/refresh'ит usage, всё приложение лагает 9-15 секунд; `updating` не заканчивается; selected label остаётся `fr***`, но проценты прыгают к `ve***`; один refresh ложно показывает `99/100% left`, а следующий возвращает прежние значения; после рестарта исчезает второй аккаунт; обе account-точки зелёные; `81% left` заполняет только 19% шкалы; пустой API response выглядит как исчерпанный лимит.
Подробнее: `knowledge/fact-claude-usage-chip.md`, `knowledge/fact-codex.md`, `methodology/диагностика-логами.flow.md`.

### Clipboard в editor-пакете (markdown-editor)
Связан с: gt-editor markdown-editor (vendored package), navigator.clipboard, Electron renderer, build:markdown sync, Vite prebundle cache, controlled-editor external-sync.
При изменении проверить:
- `navigator.clipboard` мёртв в Electron renderer (нет нативного Edit-menu) — все clipboard-пути пакета идут через инъектированный `ClipboardAdapter`, дефолт navigator (web), хост даёт `electron.clipboard`. Резолвить адаптер ОДИН раз наверху keymap'а, не per-call (забытый сайт → web-fallback сломан)
- НЕ перехватывать clipboard в хосте через `onKeyDownCapture` — capture-фаза стреляет до bubble-keymap'а редактора и глотает keymap-driven режимы (AI-paste тихо деградирует в plain paste, индикатор висит). Чинить инъекцией транспорта в пакет, не перехватом
- Cmd+X: delete НЕ внутри `writeText().then()` (data-loss на реджектящемся транспорте) — write fire-and-forget, dispatch delete безусловно в том же тике
- `readItems` омитнут в Electron-адаптере → image-paste уступает нативному DOM-`paste` handler'у (`imagePaste.ts`); не добавлять второй image-канал
- clipboard-dispatch'и сохраняют `userEvent: 'delete.cut'`/`'input.paste'`, НИКОГДА не `'external-sync'` (иначе onChange не выстрелит → tab.notes не сохранится; или ping-pong-краш — см. узел Controlled editor)
- правка исходника пакета в `gt-editor/.../src` НЕ доедет без `npm run build:markdown` (build → rsync dist → rm `.vite` cache) + полный reload (prebundled dep не подхватывается HMR); верифицировать маркеры в dist (`grep -c Clipboard:Block` > 0), не доверять exit 0
Симптом рассинхрона: Cmd+X/Cmd+C не работают молча; AI-paste вставляет обычный текст и индикатор не гаснет; правка исходника «не применилась».
Подробнее: `fix-notes-clipboard-adapter.md`, `fact-notes.md`, `fix-vite-prebundle-cache.md`.
