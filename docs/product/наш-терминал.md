# Наш терминал

## Позиционирование

Custom Terminal — это terminal-native рабочая среда для AI-агентов. Активный фокус продукта — реальные Claude Code и Codex CLI в терминале; приложение добавляет слой управления, истории, памяти, мобильного доступа и внешнего API. Gemini-интеграция остаётся legacy/partial и не входит в текущее публичное позиционирование.

Основной текущий сценарий — разработка сложных фич с несколькими параллельными
задачами и AI-сессиями. Пользователь должен видеть как можно больше вкладок
одновременно и переходить к нужной без предварительного поиска за краем окна.
По решению03.10 вкладки внутри рабочего окна всегда переносятся на следующие
строки: дополнительная высота шапки допустима, горизонтальная прокрутка ради
выбора другой вкладки — лишнее действие. Это приоритет рабочего интерфейса,
а не требование свести приложение к редактору кода.

Ключевая формула:

> История и Timeline помогают работать с контекстом живых Claude/Codex-сессий. Desktop, iPhone и MCP/API дают управлять ими и передавать работу между сессиями; настоящий терминал остаётся доступен.

Продукт решает задачи долгой работы: найти нужные итерации, передать другой сессии ограниченный контекст, продолжить управление с телефона и понять, что произошло с конкретным запросом. Основной текущий Claude/Codex-путь использует PTY; отдельная SDK-вкладка и исследовательские backend-варианты имеют свои границы. Сам выбор транспорта не доказывает конкурентную уникальность или условия оплаты.

## Что пользователь видит

Пользователь открывает проект и видит рабочее пространство:

- вкладки терминалов и AI-сессий;
- живой Claude/Codex в терминале;
- нижнюю панель управления AI: start/continue/stop, model, effort, think, context meter, copy prompt, fork;
- Timeline справа: точки сообщений, compact markers, fork/plan/session chain, активная ветка;
- History как основная поверхность Claude/Codex PTY-вкладки: markdown, diff, tool actions и range copy; тот же живой терминал доступен отдельно;
- нативный iPhone-клиент для удалённого управления; старый mobile-web является отдельным legacy-клиентом;
- MCP-доступ для других AI: запустить вкладку, отправить prompt, остановить процесс, прочитать историю, сделать fork/edit.


Главное ощущение: пользователь работает с историей и текущими задачами сессий, сохраняя доступ к реальному CLI. Операции над историей различаются у Claude и Codex.

## Основные пользовательские сценарии

### Запустить живого Claude

Пользователь нажимает `Claude`, приложение запускает реальный `claude` в PTY. После появления prompt символа приложение может автоматически отправить стартовый prompt через безопасную программную вставку. Session id подхватывается через bridge/statusline и сразу появляется в UI.

Что важно:

- используется интерактивный terminal Claude, а не `claude -p`;
- текущий логин и подписка работают как в обычном терминале;
- prompt отправляется после готовности TUI, а не "через 1 секунду";
- пользователь может в любой момент кликнуть терминал и работать руками.

### Управлять Claude из UI

Пользователь может переключить модель, effort, thinking mode, отправить `/compact`, остановить текущий ответ или продолжить сессию.

Продуктовый смысл:

- `/model` и `/effort` выглядят как кнопки, но реально выполняются в живом TUI;
- если в composer уже набран пользовательский draft, он не теряется;
- кнопки не дают отправить две конфликтующие команды одновременно;
- UI показывает, где состояние подтверждено Claude, а где это локальное намерение.

### Остановить ответ, но не убить процесс

Есть два разных действия:

- interrupt текущего turn — пользователь хочет остановить ответ и вернуться к prompt;
- stop process — пользователь хочет завершить Claude/Codex процесс, оставив shell и возможность resume.

Это критично для mobile и desktop UX. В конкурентах эти действия часто смешиваются, из-за чего кнопка Stop под input убивает всю сессию.

### Смотреть историю как дерево

Пользователь не читает сырой JSONL. Он видит Timeline:

- каждая точка — сообщение или важная граница;
- клик по точке скроллит terminal к месту;
- hover показывает превью;
- видны fork, plan mode, compact, active branch;
- можно открыть History panel и прочитать диалог как документ.

История строится не линейным чтением файла, а через backtrace по parent-связям. Отменённые Escape/Undo ветки не должны перемешиваться с активной веткой.

### Fork

Пользователь нажимает fork и получает новую вкладку с копией истории. Оригинал остаётся нетронутым. Можно попробовать другой подход, другую модель или другой prompt.

Типичный паттерн:

1. Агент зашёл в тупик.
2. Пользователь делает fork.
3. В форке удаляет/сжимает мусорный диапазон.
4. Продолжает с чистым контекстом.

### Rewind

Пользователь выбирает точку в Timeline и откатывает Claude к нужному сообщению. Приложение автоматизирует TUI-навигацию по history menu, выбирает нужный пункт и вставляет резюме того, что случилось дальше.

Это "Ctrl+Z для разговора с AI": вернуться в точку, где всё было хорошо, и пойти другим путём.

### Edit Range / Compact

Пользователь выделяет диапазон сообщений в истории, например 30 шагов неудачной отладки. Приложение заменяет их коротким summary: что пробовали, что не сработало, где оказался корень.

Пользовательский результат:

- контекстное окно освобождается;
- смысл сохраняется;
- Claude продолжает с компактной историей;
- мусорные ходы не продолжают занимать внимание и токены.

### Чтение другой сессии через Terminal MCP

Любая AI-вкладка может читать историю других открытых Claude/Codex-сессий через MCP.

Пользовательский сценарий:

- в одном табе агент пишет код;
- во втором табе другой агент тестирует;
- третий агент через Terminal MCP находит сессию, читает выбранные итерации и последний ответ;
- если нужно, можно предложить edit/fork для Claude-сессии.

Это не "подчинённые агенты", а адресуемый доступ к другим живым рабочим потокам.

### Terminal MCP

Внешний AI может управлять вкладками:

- создать или найти AI tab;
- запустить Claude/Codex;
- отправить prompt;
- остановить процесс;
- перезапустить dev server;
- прочитать terminal output как fallback.

Важно: квитанция отправки не означает готовый ответ. Для долгой межсессионной задачи `delegate_to_session` возвращает runId; после уведомления `get_delegation_result` читает итог. История и live-действия доступны через единый Terminal MCP; отдельный Overseer MCP больше не является публичной поверхностью.

### Mobile control

Основной текущий клиент — нативный iPhone Terminal Control в habit-tracker; он управляет теми же desktop-сессиями через общий API. Ниже сохранены названия состояний и контролов прежнего mobile-web: это legacy-интерфейс, не обещание идентичной текущей native-вёрстки.

- active/busy/starting/inactive status;
- Send/Stop composer;
- Resume, если процесс умер;
- model/effort для live Claude;
- context percent;
- Stop process в header.

Для Claude PTY mobile использует тот же смысл состояний, что desktop:

- `inactive` — процесс не запущен, история есть;
- `starting` — процесс запущен, prompt ещё не готов;
- `active` — prompt готов;
- `busy` — идёт turn.

## Детерминированность

Главный продуктовый принцип: UI не должен угадывать состояние по таймауту, если есть авторитетный сигнал.

Что считается авторитетным:

- sync markers Ink/TUI для готовности render frame;
- OSC 133 для shell command start/finish;
- OSC 7 для текущей директории;
- Stop hook Claude для turn busy/done;
- JSONL/rollout append для новых сообщений;
- StatusLine bridge для Claude session id/model/context;
- Codex rollout `task_started`, `task_complete`, `turn_aborted`;
- xterm markers для точных terminal-позиций.

Таймеры допустимы только как fallback: аварийно выйти, показать ошибку, защититься от зависшего стороннего TUI. Они не должны быть нормальным способом "понять, что Claude закончил".

## Почему обычный terminal parser недостаточен

Простой terminal parser видит только байты экрана. Этого мало:

- TUI может перерисовывать один и тот же экран десятки раз;
- spinner может остаться в scrollback и выглядеть как live busy;
- переносы строк и box drawing ломают plain-text diff;
- меню `/model` или `/rewind` нужно не просто увидеть, а пройти детерминированно;
- Claude JSONL содержит отменённые ветки, compact boundaries и bridge-переходы, которых нет на экране;
- после `/compact` часть parent-ссылок может вести в виртуальную память Claude, а не в файл;
- Codex compact содержит encrypted compaction state, которое нельзя расшифровать локально.

Поэтому продукт использует два слоя:

- PTY/TUI слой — чтобы управлять живым процессом;
- JSONL/rollout слой — чтобы понимать историю и результат.

## Технические фишки, которые дают продуктовую ценность

### safePasteAndSubmit

Программная вставка в Claude/Codex TUI не равна ручному `Cmd+V`. Код отправляет текст и Enter слишком быстро; React/Ink может ещё не закоммитить state, и submit увидит пустой input.

Решение:

- текст режется на безопасные чанки;
- каждый чанк идёт как bracketed paste;
- каждый чанк меньше macOS PTY-лимита;
- после вставки ждётся sync marker от TUI;
- Enter отправляется только после подтверждения render frame;
- slash-команды используют stash flow, чтобы не потерять draft пользователя.

Пользовательская ценность: кнопка `/model`, fork prompt, rewind summary и MCP prompt delivery не теряют текст и не ломают TUI.

### PTY лимит и escape safety

На macOS большие `term.write()` могут физически резаться примерно на 1024 байтах. Если разрезать escape-последовательность bracketed paste, Ink/TUI может не понять вставку.

Решение продукта:

- user paste и programmatic paste разделены;
- programmatic paste использует короткие chunks;
- escape-последовательности не разрываются;
- Enter не смешивается с paste body.

### OSC 133 вместо process polling

Shell сам сообщает, когда команда началась и закончилась. Приложение не бомбит систему `pgrep/ps` каждые 2 секунды.

Пользовательская ценность:

- точные индикаторы running/idle;
- ниже CPU;
- нет 2-секундного лага;
- меньше ложных "процесс жив/мёртв".

### OSC 7 для CWD

Shell сам сообщает текущую директорию при `cd`.

Пользовательская ценность:

- вкладка всегда знает актуальный проектный путь;
- resume/fork/MCP actions идут в правильный cwd;
- не нужно угадывать cwd через процессы ОС.

### OSC 7777 / terminal markers

Приложение ставит невидимые in-stream markers в PTY-поток и регистрирует xterm marker на точной строке.

Пользовательская ценность:

- Timeline scroll к сообщению работает по точному anchor;
- не нужно искать текст, который может повторяться;
- при росте scrollback marker сохраняет правильную позицию.

### Claude JSONL backtrace

Claude JSONL — append-only лог, а не готовый список сообщений. Escape/Undo создаёт новую ветку, но старые записи остаются в файле.

Решение:

- строить активную историю обратным обходом от текущей головы;
- идти по `parentUuid`;
- фильтровать мусорные записи;
- восстанавливать цепочку после compact/chain breaks;
- отличать fork от bridge;
- подавлять false-positive warnings после штатного compact init.

Пользовательская ценность: Timeline показывает текущую реальную ветку, а не все физически записанные попытки вперемешку.

### Compact recovery

После `/compact` Claude может сослаться на UUID, который существовал только в оперативной памяти и не попал в JSONL. Наивный parser обрывает историю.

Решение:

- fallback на обычный parent;
- fallback на физического предшественника в файле;
- отдельная логика для compact passthrough;
- no-warning recovery для штатных attachment entries.

Пользовательская ценность: старая история не исчезает из Timeline после compact.

### Session bridge

Claude session id берётся через StatusLine bridge, а не через догадку по имени файла.

Пользовательская ценность:

- UI быстро понимает, какая session сейчас активна;
- Plan Mode / Clear Context связываются в одну цепочку;
- fork не склеивается случайно с parent;
- manual session input остаётся fallback, а не основной путь.

### Codex rollout parser

Codex поддерживается как настоящий PTY-agent, не SDK. Session id берётся из `~/.codex/sessions/.../rollout-*.jsonl`.

Что умеет продукт:

- Timeline по `user_message`;
- History по `response_item`;
- context percent по `last_token_usage`, а не кумулятивному total;
- `task_started/task_complete/turn_aborted` как busy-source;
- model/effort picker через TUI, когда это безопасно.

Ограничение честно отражается в UX: Codex history сейчас read-only для Overseer edit, потому что у Codex нет Claude `parentUuid` DAG и edit-range pipeline.

## Панель управления AI

Нижняя control bar показывает только действия, которые имеют смысл для текущего типа вкладки.

Для живого Claude/Codex PTY:

- session id copy;
- Continue/Stop;
- refresh Timeline;
- fork;
- copy prompt / copy+clear;
- mic;
- Enter;
- Ctrl+C;
- context meter;
- model/effort;
- provider/think, где применимо.

Для SDK-вкладки:

- composer-oriented controls;
- модель/effort выбираются до следующего `query`;
- PTY-only действия скрыты.

Для пустой PTY:

- показываются launch actions, а не disabled Claude controls.

Пользовательская ценность: интерфейс не обещает действий, которые не могут сработать в текущем состоянии.

## Нативный iPhone и legacy mobile web

Нативный iPhone-клиент управляет сессиями на Mac. Legacy mobile-web тоже является remote surface, но не основной поддерживаемой мобильной поверхностью. Возможности внешнего Project API и Codex-only Inbox различаются.

Правила:

- composer Stop = interrupt текущего turn;
- header Stop = kill process;
- Send проходит общий scenario layer: готовность и возможность отправки/очереди во время работы определяются конкретным provider-сценарием;
- Resume не трогает live desktop draft;
- busy для composer берётся из turn hook/rollout, не из spinner glyph;
- список вкладок совпадает с desktop порядком;
- user-assigned status marker и runtime status не смешиваются.

Пользовательская ценность: можно выйти из-за компьютера и продолжить управлять тем же локальным Claude, не превращая его в отдельного бота.

## Knowledge base

Продукт хранит `docs/knowledge` как память проекта:

- `fact-*` — как реально устроены подсистемы;
- `fix-*` — баги, шрамы, почему старый подход не сработал;
- семантический поиск помогает агенту читать 2-4 нужных файла, а не весь архив;
- документация хранит не пересказ кода, а невидимый контекст: мотивацию, ограничения, опасные связи.

Пользовательская ценность: следующий агент не начинает с нуля и не повторяет уже сожжённые часы.

## Чем продукт отличается от конкурентов

Актуальная карта и источники: [анализ конкурентов](анализ-конкурентов.md). Проверка 03.10.2026 нашла существенное пересечение с Orca, HAPI, Paseo и Herdr/Heeler; прежняя таблица «большинство не умеет» не имела достаточного покрытия и заменена конкретными критериями.

| Что показывать в Noted | Что проверять при сравнении |
|---|---|
| Выборочная история и Timeline | Читаются сообщения разговора или строки экрана; что видит другая сессия |
| Управление из desktop/iPhone/MCP/API | Общая identity операции и фактически доступные действия каждого клиента |
| Работа с занятым агентом | Сообщение поставлено в очередь или вмешалось в текущий turn; какой итог подтверждён |
| Rewind/fork/edit-range | Как изменился следующий контекст; какие операции доступны конкретному provider; откат файлов отдельно |
| Возврат результата между сессиями | Завершение исполнителя отдельно от доставки итога и восстановления после обрыва |

Это направления проверки и демонстрации, не утверждение, что Noted по каждому пункту превосходит аналоги. Inbox provider API пока Codex-only; Project API имеет другую область. Полный standalone no-GUI Noted не поставляется. Исследовательские CLI-hosts не меняют этот статус.

## Что не надо обещать

Чтобы позиционирование было честным:

- не обещать "полный API Claude Code", потому что Claude TUI остаётся сторонним продуктом;
- не обещать дешифровку Codex encrypted compact;
- не выводить условия подписки и полноту native-возможностей из слов SDK/headless; проверять конкретный режим и актуальные правила провайдера;
- не обещать уникальность API/mobile/истории или exactly-once всех действий агента без сравнительной проверки;
- не обещать идеальный parser любого будущего TUI без адаптации;
- не обещать safety без permission model, если пользователь сам включает bypass.

Лучше обещать другое:

- живой terminal-first control;
- явно различимые подтверждения доставки, исполнения и результата; таймер сам по себе не доказывает успех;
- readable history вместо scrollback;
- branches/rewind/edit как рабочий процесс;
- честные статусы и явные fallback-и.

## Короткая формулировка для внешнего описания

Noted Terminal is a workspace for long-running Claude Code and Codex sessions. It combines readable history and Timeline, access to the live terminal, iPhone control, and MCP/API tools for coordinating sessions. History operations and external APIs have provider-specific capabilities.

Русская версия:

> Noted Terminal — рабочее пространство для долгих Claude/Codex-сессий: читаемая история и Timeline, доступ к живому терминалу, управление с iPhone и взаимодействие сессий через MCP/API. Возможности работы с историей и внешних API зависят от провайдера.

## Что пришло из старой заметки

Старая папка `обзор node terminal` была про Noted Terminal. Из неё перенесены актуальные продуктовые тезисы:

- это не обёртка над Claude Code, а инфраструктура управления контекстом, памятью и историей;
- главная боль AI-инструментов — потеря контекста и мусор в длинных сессиях;
- Fork/Rewind/Edit Range дают "git для диалогов";
- Timeline превращает JSONL в дерево, а не в лог;
- knowledge base делает память проекта переносимой между агентами;
- MCP/Overseer позволяют агентам читать и управлять другими сессиями;
- event-driven управление важнее фиксированных таймаутов.
