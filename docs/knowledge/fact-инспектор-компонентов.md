# Инспектор компонентов (⌥⇧) и измерение расстояний

Наведение на элемент интерфейса с зажатыми `Option+Shift` показывает рамку и путь
`файл:строка:колонка`, клик копирует этот путь вместе с фрагментом разметки, а
фиксация первого элемента превращает инспектор в линейку между двумя элементами.
Работает в установленной сборке, без DevTools и без dev-сервера.

## Две половины и почему они разделены

| Половина | Где | Что делает |
|---|---|---|
| Штамповка | `scripts/lib/inspector-stamp.mjs` (Vite plugin, `enforce: 'pre'`, до `react()`) | ставит `data-insp-path="path:line:column:tag"` на каждый JSX-элемент |
| Инспектор | `src/renderer/utils/componentInspector.ts` + `componentInspectorModel.mjs`, запуск из `main.tsx` | рамка, буфер, замер |

Штампует по-прежнему `@code-inspector/core` (`transformCode`): формат атрибута —
общий контракт, его читают `perfFreezeProbe`, `perf-incident-ui` и
`scripts/lib/inspector-private-sourcemap.mjs`. Поэтому зависимость
`code-inspector-plugin` остаётся в `package.json`, хотя её собственный Vite-плагин
больше не вызывается. `transformCode` возвращает строку, а под hook приватных карт —
`{code, map}`; плагин принимает обе формы.

Клиентская часть плагина (`code-inspector-component` из `client.iife.js`) удалена
полностью — вместе с ней ушли TCP-listener на :5678 и опции `locate`/`copy`/IDE.

## Жест

```text
⌥⇧ зажато
  hover            → оранжевая рамка + «path:line:col · tag · W×H»
  клик             → буфер: outerHTML (≤1200 симв.) + «in <tag> at path:line:col»
  M / правый клик  → элемент A фиксируется (зелёная рамка)
  hover второго    → линии по осям + «X NNpx · Y NNpx»
  клик             → буфер: оба пути, размеры, gap x/y, смещения границ и центров
  Esc              → снять A, инспектор остаётся включённым
  отпустить ⌥⇧     → оверлей исчезает
```

`Option+Shift` ничем в `src/renderer` не занято (Option используется с `[`, `]`, `\`,
`V`). `M` перехватывается только когда рамка уже стоит на элементе: ⌥⇧M даёт
печатный символ, и в композере он не должен теряться. Клик и нажатие под ⌥⇧
гасятся в capture-фазе, иначе жест ушёл бы в кнопку/чип/терминал; без модификаторов
UI работает как обычно.

Формат буфера для одного элемента сохранён с прежней реализации — пользователь к
нему привык, и он самодостаточен для вставки в Claude/Cursor.

## Контракт производительности

Это главная причина переписывания. `client.iife.js` слушал `mousemove` без rAF,
`isSamePositionNode` звал `getBoundingClientRect()` на каждом штампованном узле
composedPath **до** решения об изменении, а `renderCover` делал 12
`getComputedStyle` (border/padding/margin × 4 стороны) плюс 4 при позиционировании
подсказки. Каждое такое чтение при «грязном» DOM форсирует пересчёт стилей и
раскладки всего документа; в рабочем окне 161k узлов это давало секунды на одно
движение мыши.

Правила нового инспектора:
1. `getComputedStyle` не вызывается нигде;
2. один `getBoundingClientRect()` на **смену** элемента — сравнение по identity идёт
   **до** чтения rect (иначе коалесценция не экономит ничего);
3. движения мыши коалесцируются в один `requestAnimationFrame`;
4. элемент ищется через `composedPath()`/`closest()`, не обходом дерева;
5. оверлей — `position:fixed` + `transform` в контейнере с `pointer-events:none`;
   без `contain` (обрезало бы fixed-рамку) и без `will-change` (не держим постоянные
   слои компоновщика);
6. скролл/resize перечитывают только 0–2 обрамлённых элемента.

Замерено живьём (свой Electron-инстанс, 40 023 узла, 60 движений, стиль
инвалидируется между ними): схема upstream — 1404 мс (23.4 мс на движение), наша —
22 мс (0.37 мс). При 161k узлов разрыв больше.

Контракт закреплён тестом `componentInspector.actual.test.mjs`: он компилирует
настоящий `.ts` и считает обращения к DOM, а не проверяет текст исходника.

## Проверка сборки

`scripts/code-inspector-reproducibility.test.mjs` собирает фикстуру и требует:
штамп на каждом JSX-элементе, repo-relative пути (фикстура лежит внутри репозитория,
потому что `pathType: 'relative'` срезает именно git toplevel), отсутствие клиента
плагина в HTML и JS и ноль вызовов `net.Server.listen` за сборку.

Корневой элемент компонента получает штамп выражением
(`__codeInspectorProps["data-insp-path"] || "src/File.tsx:1:28:button"`), чтобы
родитель мог передать своё положение вниз; обычные элементы — строковым литералом.
Обе формы заканчиваются одинаковой строкой `path:line:column:tag`, поэтому
`parseInspectorStamp` берёт поля с конца: путь сам может содержать `:`.
