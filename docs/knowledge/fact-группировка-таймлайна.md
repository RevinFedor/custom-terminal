# Fact: Семантическая группировка Timeline

Группировка — это сохранённая семантическая проекция поверх плоской хронологии Claude/Codex. Она решает пользовательский симптом «в сессии 20–60 итераций, но непонятно, какие этапы мы проходили». Raw Timeline и History остаются источником правды; группа не переписывает JSONL и не подменяет UUID исходных ходов.

## Ручной контракт

Пункт «Сгруппировать Timeline» в кнопке инструментов Timeline (правая часть шапки) пересобирает **всю текущую сессию** активной вкладки. Другие проекты и сессии в AI-запрос не попадают. Это намеренно ручная, а не фоновая функция: после новых ходов старые группы не переименовываются сами, новый хвост остаётся в корне, а `+N` на кнопке показывает, сколько ходов не входит в сохранённый outline.

Структура плоская и одноуровневая. AI должен вернуть точное хронологическое разбиение всех eligible user-turns; одноходовая AI-группа сохраняется в данных, но не рисует в UI лишнюю обёртку. Вложенные группы, macro-chapters и автоматическое incremental-обновление не реализованы.

## Что получает AI

Подготовка input детерминирована до вызова модели:

- передаются только непустые user-turns текущей canonical Timeline; bootstrap, subagent-noise и технические continuation не становятся темами;
- тело compact никогда не используется как тематическое доказательство; в fingerprint попадает только структурный счётчик;
- точное prefix-совпадение с сохранённым в Settings шаблоном заменяет большое тело на content-free marker `META · <title>`; из нескольких совпадений берётся самый длинный prefix, а короткий полезный suffix может остаться контекстом;
- обычный prompt режется как head+tail, а не только с начала: после вставленного документа реальная инструкция часто живёт в конце;
- лимит одного хода — 2 400 символов, общий char-budget — 120 000, после реального `countTokens` запрос отклоняется выше 180 000 input-токенов, а не тихо теряет часть outline.

Структурные границы запрещают группе пересекать `continued`, смену session-layer, Plan, заметку, Rewind или fork-boundary. AI видит короткие ссылки `p0001…pNNNN`, а не длинные синтетические UUID. Одна ошибочная цифра в UUID уже давала `Unknown Timeline prompt UUID`; короткие refs локально маппятся обратно, а unknown ref остаётся hard failure. Fuzzy-repair здесь недопустим: он мог бы привязать группу к другому ходу.

Два Gemini-ограничения закреплены на границе API. `countTokens` отвергает `systemInstruction`, хотя generation его принимает; поэтому для подсчёта system+request объединяются в обычный content. Большой `maxItems` в nested response schema даёт недиагностичный `INVALID_ARGUMENT`; cardinality убрана из provider-schema и проверяется локально вместе с exact coverage, порядком и границами. Более дорогая модель уже нарушала exact coverage, поэтому цена модели не заменяет детерминированную валидацию.

## Проекция в раскрытом Timeline

Заголовок группы — synthetic row, а не первый user-turn. Он показывает wrapping-title и число основных итераций; декоративный ромб, role-chip и compact-count убраны, потому что они отнимали ширину у названия. Header остаётся sticky внутри Timeline-scroll, пока его не сменит следующая группа. Cmd-hover на header показывает только описание этапа, не повторяет видимый title/count. Короткие английские group titles допустимы: в узкой колонке они часто короче, а язык индивидуальных action rows остаётся языком prompt.

По умолчанию последняя группа раскрыта, а collapse-state хранится по `tool + session + stable group id`. Активная range-операция временно раскрывает все группы. Группа также принудительно открыта, если в ней есть заметка, Rewind-marker, fork/session/memory-boundary: структурные affordance не должны исчезать из-за semantic collapse.

Все клики, History-scroll, Rewind, notes и range-actions разрешаются обратно в raw UUID. Группа не может стать новым address-space. Сохранённый outline применяется только после полной локальной валидации; partial outline не «дочиняется» эвристикой.

## Compact принадлежит группе

Технический compact не может остаться «сиротой» между двумя свёрнутыми группами. Compact между группами принадлежит предшествующей фазе, потому что сжимает накопленный до него контекст; leading compact привязывается к первой группе, trailing — к последней. Свёрнутая группа скрывает и ходы, и принадлежащие ей compact-строки.

В Codex пара `compacted → context_compacted` и пустые технические continuation не размножают одно сжатие. Реально соседние semantic compacts показываются как `compact ×N`; единичный — как `compact`, без бесполезного `×1`. В header группы compact-count не выносится. Codex compact не имеет человекочитаемого summary, поэтому Cmd-hover не запрашивает full History и не изобретает «контекст». Явное `Копировать compact` остаётся отдельным capability: оно может развернуть verbatim `replacement_history` с маркером encrypted state. Claude compact остаётся другим классом: у него есть читаемый summary.

В свёрнутом 32px rail соседний compact-кластер остаётся одной оранжевой точкой. Для `N > 1` число показывается маленькой светло-янтарной цифрой справа сверху; она абсолютно расположена в свободном месте с зазором от точки, поэтому не меняет ширину Timeline и координаты остальных маркеров. Для `N = 1` цифры нет.

## Название отдельного хода

Видимая строка описывает действие или вопрос пользователя, а не жанр сообщения и не выдуманный результат: `Проверить конфликт инструментов с WebODM`, а не `конфликт исправлен` и не `запрос на анализ`. Приоритет источников: ручной action override → Prompt Summary → member-description из outline → bounded raw prompt.

ПКМ → `Обновить название` — repair-path для плохой диктовки или двусмысленного prompt. Он доступен только когда у хода есть завершённый assistant-response. Ответ — недоверенное свидетельство для расшифровки intent, а не право приписать агенту успех. Последняя busy-итерация возвращает `Ответ ещё не завершён`. Override хранится отдельно от outline и не стирается повторной группировкой.

Служебные role вроде `stage`, `documentation` и `clarification` остаются machine metadata. Они не рисуются отдельной строкой в Cmd-hover: третья параллельная сущность только ухудшала сканирование.

## Владение и async-границы

Outline хранится отдельно от raw JSONL и `timeline_notes` и ключуется по `toolType + sessionId`; action overrides и Prompt Summary — по `toolType + sessionId + entry UUID`. HistoryPanel остаётся плоской canonical-проекцией, а synthetic group header существует только в Timeline и не становится новым адресом истории. Переключение вкладки не имеет права соединить новый session id с массивом entries предыдущей вкладки. Late AI-response применяется только к immutable owner snapshot и canonical UUID set, но не по совпадению `entry.sessionId`: resume-файл законно содержит несколько session IDs.

Групповой Cmd-hover привязан к stable group id, а не к ссылке на новый `semanticGroups[]`. Обычный transcript refresh создаёт новый array даже при тех же ID. Сброс hover-state по array identity давал точный симптом: popup исчезал под неподвижным курсором и не открывался по новому Cmd, пока курсор не выйдет из Timeline. Правильная hydration сравнивает stable ID-signature и сбрасывает active group только когда исчезла сама сущность или сменился owner.

## Осознанные не-цели

Текущая версия не скрывает чистые `продолжай` в meta-continue, не синхронизирует scroll Timeline и History, не строит вложенные chapters и не перегруппировывается автоматически. Это открытые продуктовые решения, а не скрытая функциональность.
