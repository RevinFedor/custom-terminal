# Справка и короткие Cmd-подсказки

## Три разных способа объяснять интерфейс

Интерфейс не пытается объяснять все действия одним универсальным popover. Выбор
зависит от сложности и от того, занят ли уже `Cmd` настоящим действием:

1. Неочевидный icon-only контрол без собственного `Cmd`-поведения получает
   короткую пассивную подсказку (`ControlHint`). Она появляется только при
   физическом наведении и удержании `Cmd`.
2. Контрол с собственным modifier-действием или подробным preview остаётся у
   владельца фичи. Общая подсказка не должна создавать поверх него второй
   popover и менять его действие.
3. Многошаговый пользовательский сценарий объясняется на общей странице
   «Справка»: короткая подпись не заменяет последовательность состояний и видео.

Переключатель «Подсказки интерфейса» управляет только первым режимом. Он не
выключает `Cmd+click`, drag, контекстные меню, подробные preview или реальные
действия контролов. Сейчас настройка хранится в runtime-store и после нового
запуска возвращается к включённому состоянию.

## Контракт короткой подсказки

- Одновременно должны существовать физический hover и удерживаемый `Cmd`.
  Нажатие `Cmd` после ухода курсора не открывает старый контрол: перед показом
  общий `Tooltip` заново проверяет `:hover`.
- Одна общая keyboard-подписка ещё не защищает от лишней работы: рассылка Cmd
  всем React-setter'ам перерисовывала даже закрытые подсказки сохранённых панелей.
  React получает клавишу только для наведённой/открытой подсказки; при входе с
  уже удерживаемым Cmd она читает актуальный физический флаг. Оба порядка
  hover→Cmd и Cmd→hover, bridge, отпускание и blur должны сохраняться вместе.
- Подсказка пассивна (`interactive=false`): она не закрепляется, не принимает
  pointer/click и не создаёт hover-bridge.
- Обёртка только объясняет действие. Она не реализует само действие и не меняет
  обработчик дочернего контрола.
- Пока короткие подсказки включены, native `title` у обёрнутого активного
  контрола скрывается, чтобы две подписи не накладывались. У disabled-контрола
  native `title` сохраняется как единственное объяснение недоступности.
- Динамический текст вычисляет владелец контрола из текущего состояния. Общая
  подсистема не должна угадывать смысл кнопки.

Короткие подсказки используются для неочевидных действий в верхней навигации,
Dashboard, File Explorer, Browser, History/Timeline toolbars, нижней AI-панели,
StatusBar, Run after и модальных панелях. Явные текстовые кнопки, пункты меню и
обычные form-controls отдельной подсказки не требуют. Rich surfaces сохраняют
свой собственный контракт.

## Общая страница справки

Кнопка `?` сразу открывает одну страницу без промежуточного меню. На ней есть:

- короткая модель продукта: живой PTY исполняет команды, JSONL/rollout хранит
  историю, а Desktop/iOS/MCP/API управляют той же сессией;
- строка «Подсказки интерфейса» с переключателем и местом под короткое видео;
- горизонтальный список реально заполненных сложных тем;
- создание диагностического TXT с описанием проблемы и выбранным периодом.

Старого блока «Ключевые операции» со ссылками на сайт на этой странице нет.
Пустые темы заранее не создаются: новый tab появляется только вместе с готовым
содержанием.

Первая сложная тема — `Restart after`. Она объясняет пользовательскую цепочку:
выбрать одну или несколько AI-вкладок, выбрать script или использовать
подходящую последнюю команду, увидеть фиолетовый marker, поставить подписку на
паузу без потери настроек и очистить её через `Cmd+click`. Полный runtime-
контракт находится в [`fact-scripts.md`](fact-scripts.md), а сквозной flow — в
[`сценарии-использования.md`](../methodology/сценарии-использования.md).
