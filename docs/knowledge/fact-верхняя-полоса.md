# Feature: верхняя полоса окна и инструменты боковой панели

## Intro

Наверху окна ОДНА строка (`TITLE_BAR_H = 30`, `src/renderer/constants/layout.ts`): слева карточки проектов, справа кнопки рабочей области (`WorkspaceTitleBarTools.tsx`). Кнопки самого проекта живут не здесь, а первой строкой внутри боковой панели вкладок (`SidebarToolsRow.tsx`, высота `SIDEBAR_TOOLS_H = 30`).

**Второй строки во всю ширину окна больше нет (2026-08-18).** Раньше под шапкой шла полоса `ProjectToolbar` на 30px через весь экран, и в ней стояло всё сразу. Она забирала высоту у терминала на каждом экране ради десятка кнопок, при этом её левая половина говорила про ОДИН проект — тот же, чей список вкладок шёл ниже, а справа от карточек проектов в шапке и так всегда пустовало место, отданное под перетаскивание окна.

Разъехалось по хозяевам:

- **кнопки проекта** (файлы проекта, история вкладок, сжать логи, VS Code, GT Editor, состояние индекса, возобновить прерванные) — в боковую панель, над списком вкладок того же проекта;
- **кнопки рабочей области** (⌘P, настройки external Codex, инструменты Timeline, расход ресурсов, расход токенов, Docs, копирование сессии, Git) — наверх, в свободную правую часть шапки;
- **справка** — вниз, в строку состояния (см. [`fact-status-bar.md`](fact-status-bar.md)).

Компонент `ProjectToolbar.tsx` удалён. Метка `data-project-toolbar` переехала вместе с правым кластером: по ней всплывающие панели Git и расхода токенов ищут свою опорную полосу.

## Инструменты проекта (боковая панель)

`SidebarToolsRow.tsx` — первая строка внутри `TabSidebar`, над вертикальным списком вкладок.

| Кнопка | Иконка | Действие |
|---|---|---|
| Файлы проекта | `PanelLeft` | Открыть/скрыть выезжающий файловый проводник (⌘B). Подсвечена, пока проводник открыт. |
| История | `History` (только иконка) | Открыть вид проекта с историей вкладок: закрытые сессии, поиск по ним, превью. Подсвечена, когда этот вид открыт. |
| Сжать логи | `Minimize2` | Сжать логи из буфера обмена (`utils/compressLogs.ts`). |
| VS Code | `VscVscode` | `exec('code .', { cwd })` — директория активной вкладки ЭТОГО проекта или путь проекта. |
| GT Editor | `FileEdit` | `shell.openExternal('gteditor://open?folder=<cwd>')` — фокусирует уже запущенный GT Editor (или запускает) через macOS LaunchServices. Внутри редактора `Ctrl+G` принимает `path:line:col`. |
| Индекс | переменная (см. ниже) | Состояние `.semantic-index.json`; клик — переиндексация; ПКМ — настройки. Режим значка (`compact`). |
| Возобновить | `RotateCcw` + число | Появляется ТОЛЬКО когда в этом проекте есть прерванные сессии. |

**Хозяин ряда — переданный `projectId`, а не активный проект.** Панелей на экране может быть несколько (по одной на видимый проект). Ряд обязан отвечать за проект, над списком которого он нарисован: директорию берёт у активной вкладки СВОЕГО проекта (`workspace.activeTabId`), а не через общий `getEffectiveTabId()`. Иначе «открыть в VS Code» из одной панели открывало бы директорию соседней. Хоткей ⌘G — исключение наоборот: он глобальный, поэтому висит только на панели проекта в фокусе, иначе фоновые экземпляры перехватывали бы его друг у друга. Закреплено `components/Workspace/topStripLayout.wiring.test.mjs`.

**Мера кнопки — общая с кнопками рабочей области:** высота 26, шрифт 11, отступы `0 6px`. Две разные меры кнопки в одном окне читаются как два разных приложения, поэтому экономить здесь на размере нельзя — экономить можно на подписях, что и делается. Высота ряда (`SIDEBAR_TOOLS_H`) считается ОТ кнопки, а не наоборот.

**Кнопки шапки отвечают на курсор — все.** Кнопка, которая молчит под курсором, читается как подпись, а не как то, что можно нажать; соседи по строке при этом подсвечиваются, и разница выглядит поломкой. Исключение одно и оно осмысленное: кнопка со СВОИМ цветом состояния (открыта панель, идёт работа, включён авто) на курсор не отвечает — её подложка уже занята под сообщение о состоянии, и подсветка поверх соврала бы «наведено» там, где уже сказано «открыто».

**Ряд переживает узкую панель.** Ширина боковой панели настраивается от 140px, кнопки идут значками с рамкой и зазором 3px (подписи нет — она бы не поместилась, объяснение живёт в подсказке), у ряда своя горизонтальная прокрутка со скрытой полосой — иначе последняя кнопка просто уходила бы за край без следа, а видимая полоса прокрутки съела бы пятую часть высоты ряда.

Кнопка глобального Run After остаётся последним контролом этого ряда и показывает
короткую подпись `run-after · N`: строчные буквы и дефис сохраняют смысл при
узкой ширине, а счётчик активных очередей остаётся видимым.

**Кнопка индекса в узком ряду показывает состояние, а не все свои числа** (`compact`). Полные отступы в 12px и три числа вытеснили бы соседей. Остаётся то, ради чего на неё смотрят: цвет состояния и число отставших файлов; количество актуальных, множитель воркеров и подпись «no index» уходят в подсказку. Смысл состояний не меняется.

**Кнопки видны только в рабочей области** (`view === 'workspace'`). На Dashboard рабочей области нет, и кнопки там управляли бы проектом, которого не видно.

**`WebkitAppRegion: 'no-drag'` обязателен.** Шапка тащит окно за любое пустое место; без этого клик по кнопке начинал бы перетаскивание вместо нажатия.

**Кнопка Git завёрнута в коробку с высотой и обрезкой углов.** Она рисует себя во всю высоту хозяина и с прямыми углами — так было верно в полосе, где она упиралась в правый край окна. В шапке края нет, поэтому высоту задаёт обёртка, она же обрезает скругление.

## Две высоты, которые обязаны совпадать

`TITLE_BAR_H` (`constants/layout.ts`) и `titleBarOverlay.height` (`src/main/main.js`) — одно число в двух местах. В этой полосе macOS сам рисует кнопки закрыть/свернуть/развернуть; если числа разойдутся, кружки встанут не по центру шапки, и поправить это вёрсткой нельзя — они рисуются поверх окна. Проверяется тестом, который читает оба файла.

Производные того же числа:

- `TOP_STRIP_H` — всё, что выше рабочей области. Против него стоят через `position: fixed` панель переключателя вкладок и переключателя проектов;
- `EXPLORER_TOP_H = TITLE_BAR_H + SIDEBAR_TOOLS_H` — верх выезжающего файлового проводника. Он открывается кнопкой из ряда инструментов и начинается ПОД этим рядом: панель поверх собственной кнопки читается как «кнопка исчезла».

## Строка проектов сжимается, а не выдавливает кнопки

Строка теперь одна на всё: карточки проектов делят её с кнопками справа. У списка карточек своя горизонтальная прокрутка со скрытой полосой и обязательный `min-w-0` — без него flex-блок отказывается сжиматься и выпихивает соседей за край окна. Это и есть тот случай «проекты не помещаются», ради которого прокрутка добавлена.

У карточек есть потолок высоты (`PROJECT_CARD_MAX_H = 24`): вертикальные отступы карточек настраивает пользователь (Settings → Размеры → Проекты), и без потолка карточка вылезала бы за край низкой шапки. Ограничение только по вертикали — по ширине карточки свободны.

**Pair-aligned popover'ы.** Оба popover'а (Docs и Copy-session) открываются downward-right-aligned относительно триггера: `top: bRect.bottom + 6, right: window.innerWidth - bRect.right`. Cmd+. больше нигде не висит.

## External Codex run settings

Кнопка настроек external run — локальный control активной Inbox-вкладки, а не общая настройка проекта. Внешний клиент (например Voice Record) владеет своим чатом, но Noted Terminal владеет видимой Codex-вкладкой, поэтому пользователю нужен быстрый доступ именно здесь: свернуть/развернуть бейдж external run, изменить stop процесса в секундах и закрытие вкладки в минутах.

Stop процесса и close вкладки — разные оси. Stop завершает Codex runtime после `done`, а close убирает визуальную вкладку после отдельного countdown, чтобы system Inbox не копил старые external runs. Collapsed badge оставляет маленький статусный маркер без захвата высоты терминала; развёрнутый badge показывает источник, process countdown и tab countdown.

Видимость кнопки не должна зависеть только от живой app-server metadata: при hot reload/restart renderer может восстановить вкладку раньше, чем external-run map снова появится. Поэтому `externalRun` сериализуется в SQLite, а для старых Inbox Codex-вкладок toolbar имеет fallback по признаку `Inbox + commandType=codex + name starts "Codex ·"`. Без этого пользователь видит выбранную `Codex · ...` вкладку на Home-виде, но кнопки настроек нет вообще.

## SemanticIndex visual language

Цвет = sentiment, не информация. Информация — цифры справа от иконки.

| Состояние | Иконка | Цвет | Текст |
|---|---|---|---|
| Idle, всё актуально | `CircleCheck` зелёный | `#22c55e` | `<fresh>` (одно число) |
| Idle, есть устаревшие/новые/удалённые | `CircleCheck` зелёный + `AlertTriangle` амбер | `#22c55e` + `#d97706` | `<fresh>` ⚠ `<stale+new+removed>` |
| Idle, индекса нет | `AlertTriangle` амбер | `#d97706` | `no index` |
| Running | `Loader2` амбер (вращение) + фиолетовый чип параллелизма | `#d97706` + `#a855f7` | `<done>/<outdated_total>` ×`<parallelism>` |

**Третий чип (фиолетовый ×N) появляется только в Running.** Стартует как `×1`, затем обновляется из live MCP progress (`active` воркеры). На scan-фазе `workerLimit` может быть больше 1, но чип не поднимается до `×2/×3`, пока MCP реально не запустил столько Codex-процессов одновременно. При смене настройки mid-rebuild чип остаётся привязан к текущему progress — новое N применится к следующему запуску.

**ПКМ на кнопке → открывает Settings на вкладке «Системные».** Реализовано через `window.dispatchEvent(new CustomEvent('settings:open', { detail: { tab: 'colors' } }))`; App.tsx слушает событие, выставляет `settingsInitialTab` и открывает модалку. Mechanism work for всех состояний кнопки (idle/no-index/running). Без этого юзеру пришлось бы помнить путь Cmd+, → таб «Системные».

**Янтарный, не жёлтый** — `#d97706` (`amber-600` в Tailwind palette). По правилу из CLAUDE.md секция «AI-Optimized UI & Video Forensics»: чистый жёлтый плохо читается на тёмной теме, янтарь сохраняет читаемость и в скринкастах.

**Почему cached не считается в running-счётчике** — см. `methodology/дизайн-принципы.md::Прогресс-индикатор показывает active work, не total volume`. Кратко: cached пролетают за миллисекунды, и `5/90` создаёт иллюзию «осталось много» там, где реально осталось 5.

**Tooltip разбивка** — показывает числа отдельно (`fresh / stale / new / removed`) плюс `docsTotal` / `indexedTotal` для отладки. В running-режиме — `activeWorkers/workerLimit` и `currentFile` (последний файл, который MCP начал индексировать).

## Watcher lifecycle (main)

Один `fs.watch`-treeset на каждый открытый проект, **не только на активный**. Это контринтуитивно (кнопка-то рендерится в боковой панели активного проекта), но необходимо для двух сценариев:

1. **Пользователь правит docs в IDE с открытым проектом A**, потом переключается на проект B и обратно — должен сразу увидеть актуальные числа на A без задержки на recompute при возврате.
2. **Mobile bridge / sub-agent** в другом проекте триггерит правку — индикатор обновляется в реальном времени, юзер не должен дёргать кнопку «обновить статус».

Lifecycle:
- App.tsx подписан на `useWorkspaceStore` + `useProjectsStore` (Zustand subscribe, не useEffect — иначе теряется реактивность на mid-cycle add/remove). При появлении нового projectId в `openProjects` keys → IPC `semantic-index:watch`. При исчезновении → `semantic-index:unwatch`.
- В main `startWatching` рекурсивно walk'ает `docs/` (исключая `tmp/`, `.dot-папки`) и навешивает `fs.watch` на каждую директорию + ещё один на корень проекта (ловит ре-запись `.semantic-index.json` после MCP `docs_reindex`).
- Debounce 300ms перед recompute (избегает 90 пересчётов когда индексатор переписывает индекс одним write).
- При quit'е процесса — `process.on('exit', cleanupAll)` снимает все watcher'ы.

**Trade-off:** одновременно 5 проектов = 5 × N директорий watcher'ов. У `fs.watch` на macOS лимит FSEvents практически бесконечный (тысячи), для 5-10 проектов с 3-5 поддиректориями каждая — это десятки, не сотни.

## Rebuild via MCP

SemanticIndexButton не запускает repo-local shell script. Клик идёт так:

```
SemanticIndexButton
  → ipcRenderer.invoke('semantic-index:rebuild', { projectId, parallelism })
  → semantic-index-status.js::rebuildIndex()
  → node ~/.claude/mcp/knowledge-server.mjs
  → MCP tools/call docs_reindex({ projectPath, parallel, provider: 'codex' })
```

Source of truth для индексации — knowledge MCP. Repo-local shell-индексатор удалён из проектов, чтобы не было второго индексатора с отдельными лимитами/моделями. MCP `docs_reindex` по умолчанию использует `codex exec` (`gpt-5.4-mini`, effort `low`) и при включённых kill-switch'ах коэрсит Gemini/Claude provider/model в Codex.

`semantic-index-status.js` сам является маленьким MCP JSON-RPC клиентом: спавнит `knowledge-server.mjs`, отправляет `initialize`, затем `tools/call docs_reindex`, парсит text-result как JSON и уже из `success/error/summary/failures` строит toast. Старый контракт stdout-regex'ов больше не используется. Live progress идёт отдельными строками stderr с marker `__KNOWLEDGE_REINDEX_PROGRESS__`; это side-channel, финальный JSON-RPC result остаётся source of truth.

**PATH augmentation для production spawn:** production `.app` запускается launchd'ом с минимальным PATH `/usr/bin:/bin:/usr/sbin:/sbin` — без Homebrew (`/opt/homebrew/bin`, `/usr/local/bin`) и user-local (`~/.local/bin`, `~/.codex/bin`). MCP path добавляет эти директории перед оригинальным PATH, чтобы найти `node` и `codex`.

**Failure semantics:** success берётся из результата `docs_reindex`, не из exit code MCP process. Если MCP вернул `success:false`, renderer получает красный toast с `result.error`; `.semantic-index.json` не должен перезаписываться частичным/битым индексом.

**Parallelism wiring (Settings → Системные → Параллельные воркеры):**

- `useUIStore.semanticIndexParallelism` (localStorage-only, 1..20, default 10).
- При клике на SemanticIndexButton renderer передаёт значение в `semantic-index:rebuild` IPC.
- `rebuildIndex(projectId, mw, { parallelism })` в main clamp'ит к [1, 20], сохраняет live snapshot и передаёт `parallel` в MCP `docs_reindex`.
- `rebuild-started` IPC payload сидит на `parallelism: 1` и `workerLimit`; renderer показывает `0/N ×1` сразу, без ожидания `get-status`.
- `semantic-index:progress` обновляет `outdatedCompleted`, `activeWorkers`, `workerLimit` и live `parallelism` по MCP marker'ам.
- `get-status` возвращает `rebuildParallelism` — переключение проекта mid-rebuild не теряет чип.
- Не доверяем raw значению из renderer (вдруг кто-то bypass'ит UI) — clamp на main-стороне обязателен.

ANSI escape codes (`\x1b[0;32m` и т.п.) стрипаются регексом перед матчингом.
