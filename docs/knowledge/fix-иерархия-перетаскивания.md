# Fix: иерархия при перетаскивании

## Пользовательские симптомы

Во вкладках родитель с дочерними строками при монотонном движении вверх или вниз мог расщепляться: строки менялись местами, затем возвращались, у соседей на один кадр появлялся фон. При движении только влево/вправо подсвечивались строки сверху, а после indent следующий Y-шаг продолжал работать по старому parent. Попытка выйти из группы или пересечь чужую ветку выглядела как несколько противоречащих друг другу решений одного жеста. В редакторе промптов горизонтальное вложение сначала отображалось, но после отпускания исчезало; пустая группа не принимала промпт, а отпускание уже за пределами списка иногда сохраняло последнюю иерархию.

Эти симптомы принадлежат одному классу: плоский порядок, visual-parent и container рассчитывались разными ветками, которые по очереди перезаписывали результат друг друга.

## Почему прежняя модель дёргалась

Старый вертикальный расчёт вкладок вынимал из порядка только строку родителя. Его собственные descendants оставались обычными target-строками, поэтому пересечение ребёнка сначала ставило родителя после него, а соседний зазор возвращал блок назад. Отдельная ветка вертикального drop одновременно угадывала нового visual-parent, хотя пользователь не делал горизонтальный жест. Один snapshot геометрии не лечит resolver, который сам строит неверное дерево.

Источник и чужая цель должны резолвиться как транзитивные визуальные блоки. Собственные descendants не являются внешними целями; чужой child представляет границу всего чужого subtree. Multi-selection сначала нормализуется по видимому порядку и удаляет элементы, уже покрытые выбранным предком. Вертикаль меняет порядок, горизонталь меняет parent, вход в группу меняет container.

Для раскрытой группы header и участники не могут иметь независимые midpoints: это одна union-boundary с hysteresis. Фон всего блока означает crossing до/после, membership выбирается отдельным slot внутри body. Оси также взаимоисключаются на кадр: X-intent приостанавливает vertical target, а после parent-change Y возобновляется из новой hierarchy revision. Именно отсутствие этих двух границ создавало повторное `before → after → before` без нового движения курсора.

Попытка хранить полный будущий state только для commit, а renderer'у показывать урезанную версию оказалась неверной: пользователь видел одну глубину и группу, а mouseup сохранял другую. Source нужно удерживать смонтированным через стабильную identity строки и единую list-проекцию, а не через вторую semantic truth. Видимый порядок, parent/container assignments и drop теперь берутся из одного immutable preview; transport применяет только последнюю отрисованную устойчивую revision.

Отдельный first-X шрам возник уже в этой модели. Подпороговый horizontal-intent очищал `targetKind=group-block`, поэтому на пороге start/middle больше не знали, в какую раскрытую группу пользователь целился, и attach'ились к предыдущей вкладке; end случайно работал, потому что группа оставалась предыдущим блоком. Group-target сохраняется сквозь подпороговые X-кадры, а первый принятый шаг сразу повторно разрешает текущий Y в child-plane. Это не общий повторный vertical resolve, а перенос второй координаты того же жеста в новую иерархию.

## Шрамы редактора промптов

После принятого шага вправо следующий обычный `pointermove` снова запускал плоский reorder. Generic flat-move трактовал его как detach и снимал только что назначенного родителя. Вертикальное движение ungrouped prompt теперь сохраняет текущую parent-связь; detach остаётся только явным шагом влево.

Выход корневого промпта из группы очищал container у поддерева, но сохранял локальные позиции `0, 1`. Без отдельной переиндексации блок прыгал в начало общего списка. Правильная позиция выхода — сразу после всего блока бывшей группы, внутренняя связь parent→child не меняется.

Пустой group-body раньше считался целью только при наличии отдельного placeholder-узла. После удаления текста «Перетащите сюда промпт» прозрачная зона осталась в DOM и геометрии, но resolver её игнорировал. Само тело пустой группы является fallback drop-зоной; instructional placeholder не должен быть скрытой функциональной зависимостью.

Проверка outside обязана выполняться раньше горизонтального `deltaX`. Иначе курсор уже за правой границей списка успевает назначить нового parent, а mouseup коммитит его как последний preview. При выходе очищаются и semantic target, и horizontal intent; commit без актуальных `pendingNext + target key` возвращает base без записи.

## Шрамы host-интеграции общего file explorer

Общий renderer не может завершить физический move за host. У свёрнутой цели ленивое дерево хранит `children=[]`; optimistic insert одного перенесённого файла превращал этот неполный снимок в якобы полный, поэтому после раскрытия старые дети исчезали только в UI. Быстрый optimistic commit сохраняется, но после успешного filesystem move оба host-приложения перечитывают дерево с диска и заменяют проекцию.

Manual layout и сохранённая сортировка должны загружаться одним решением. Раньше remount сначала восстанавливал общий ручной порядок, затем поздний ответ старой настройки `name-asc` переключал renderer обратно; poll видел ту же revision и уже не возвращал manual. Наличие записей layout означает manual независимо от порядка прихода двух async-ответов.

Shift-range строится по уже применённому видимому layout, а не по сырому filesystem-tree. Иначе пользователь выделяет четыре соседние строки, а store получает другой диапазон; последующий multi-drag выглядит как потеря или самовольное добавление файлов. Выбранные потомки нормализуются под выбранными предками, а папка остаётся одиночным атомарным блоком и не входит в файловый multi-select.

Старая схема `Cmd = physical folder-drop` была отвергнута: она давала другой смысл той же папке и не могла заранее показать точный результат. Файл и папка теперь используют один hierarchy resolver; Cmd замораживает уже показанный slot только для loader/toggle закрытой папки. Mouseup под Cmd сохраняет frozen slot, а не контейнер под курсором.

Отдельный lifecycle-шрам проявился только при release правее TabBar: Chromium не прислал ни `drop`, ни `dragend`, и live-preview оставался в DOM. Cleanup по следующему capture `mouseover` с `buttons=0` запускается с задержкой и отменяется настоящим drop; он очищает press/preview/cursor, но не имеет права коммитить last target. Валидный drop остаётся единственным автором store write.

## Первый вертикальный шаг в общем outline

После миграции TabSidebar проявился симптом, похожий на старый oscillation, но уже с двумя другими причинами: пользователь зажимал вкладку, делал первое движение вверх, а строка сначала опускалась вниз. В core граница вычислялась через высоту source-row, хотя реальный pitch списка равнялся `height + CSS gap`; накопленная ошибка в несколько пикселей выбирала соседний boundary в неверную сторону. Исправление измеряет фактические `top` всех строк, строит detached boundary geometry с реальными промежутками и не принимает DOM-order, который ещё отстаёт от controlled preview.

Вторая причина находилась не в resolver. Пустая секция Utils условно монтировалась только после начала drag, уменьшала высоту main-scroller и меняла `scrollTop`; всё дерево физически уезжало в момент захвата, хотя semantic order не менялся. Внешний drop-target теперь не участвует в flex-layout источника: для пустой Utils появляется абсолютная overlay-зона только после направленного движения вниз, а движение вверх не меняет `clientHeight`, `scrollHeight` и `scrollTop`.

Диагностически эти классы различаются так: неверный boundary меняет preview-order при стабильной геометрии scroller; host reflow сохраняет order, но одновременно меняет rect строк или размеры scroller. Поэтому при повторении сначала логируются оба набора данных, а не подкручивается threshold вслепую.

## Подтверждение

Trusted Electron-прогоны подтвердили атомарное пересечение собственного и чужого subtree, перенос групп с участниками, вход/выход поддерева из пустой группы, многоуровневые indent/outdent, смену X→Y в одном удержании, multi-selection в обратном порядке, autoscroll в обе стороны и persistence после перезапуска/переоткрытия Settings. Отдельная матрица первого X доказала start/middle/end без дополнительного Y (`15:25:32.592`, `15:27:38.171`, `15:29:43.922`): DOM-preview и SQLite после drop совпали, `attach-to-previous-peer` отсутствовал. Outside и системный Escape очистили feedback до mouseup без записи; CDP `electron_press Escape` нативный HTML5 drag не отменяет, поэтому `dragend dropEffect=none` этим каналом не считается доказанным. Ранний release до отрисовки новой проекции также дал ноль commit.

Post-drop reveal большой раскрытой группы показывает корень и до трёх первых помещающихся descendants, а не хвост всего блока. Это отдельно проверено после edge-autoscroll вниз и вверх: один физический drop дал один commit, группа сохранила всех участников.

После миграции обеих поверхностей на shared outline отдельный trusted Electron-прогон подтвердил, что первое движение SLOT 2 вверх оставляет scroller `818px`, `scrollTop=1.369` и исходный order; пересечение границы даёт `SLOT 2, SLOT 1`, обратный путь восстанавливает baseline. Тот же путь прошёл для `Prompt 4 ↔ Fix Error`. Реальный main→пустая Utils commit не менял высоту main во время удержания, после reload вкладки, группы и prompt-parent связи сохранились; полный набор pure/host-тестов прошёл `120/120`.
