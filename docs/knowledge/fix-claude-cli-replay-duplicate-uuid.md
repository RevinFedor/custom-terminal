# Fix: Claude CLI Replay Creates Duplicate UUIDs After Escape

### Симптомы
- После Escape прерывания Claude и нового сообщения — Timeline и Claude resume показывают только последние ~5-10 записей, хотя в JSONL физически есть сотни
- Контекст сессии резко падает (например, 40% → 5%) после Escape во время tool_use
- В сессии "пропадают" итерации работы: ответы Claude и user-сообщения после прерывания не отображаются, хотя они есть в JSONL
- Первая мысль "сработала очистка истории" — НЕВЕРНА. Файл цел, ничего не удалено

### Корневая причина: replay тех же tool_results

Claude Code CLI v2.1.119 при определённых сценариях прерывания **записывает один и тот же `tool_result` дважды** в JSONL.

**Триггер 1 — Escape во время текущего turn'а (сценарий A):**
1. Пользователь отправляет запрос → Claude вызывает N параллельных tool_use
2. Часть tool_results прилетает в JSONL (3 из 5 docs_search)
3. Escape прерывает поток
4. Пользователь отправляет новое сообщение → CLI делает internal resume → повторно записывает те же tool_results с **тем же UUID, тем же timestamp, новым `promptId`**
5. Дубликаты идут **подряд** в конце файла. Между оригиналами и дубликатами в файле есть streaming output (Branch A с реальной работой)

**Триггер 2 — Resume после длинной паузы (сценарий B):**
1. Сессия работает часами, Claude вызывает много tool_use в разных turn'ах (07:09, 07:56, 09:15, 09:29...)
2. Прерывание (Escape, crash, /clear) — точная природа неясна
3. При новом промпте CLI собирает контекст и видит pending tool_use'ы из **разных мест истории**
4. Re-injects их results **разбросанно** — все с одним новым `promptId`, но timestamp оригиналов сохранён
5. Дубликаты идут плотным блоком (например, idx 1724-1730), но **оригиналы разбросаны по всему файлу** (idx 11, 83, 98, 104, 108, 1186, 1289)

В обоих случаях: тот же UUID появляется в JSONL дважды, причина одна — internal replay механизм CLI.

### Что ломается в backtrace

Backtrace строит `recordMap: uuid → record` обходом файла. При коллизии Map хранит **последнее значение** — то есть второй экземпляр (line 4276) перетирает первый (line 3810). Backtrace от tip файла идёт по parentUuid:

- Сейчас на line 4276 живёт `1dc004eb`, его `parentUuid = 8d688e10` (общий родитель обеих веток)
- Backtrace перепрыгивает с `1dc004eb` сразу на `8d688e10`, минуя всю Branch A (lines 3811-4271)
- В Branch A записи имеют `parentUuid → ae099efe` (line 3803), но та запись — `assistant`-сиблинг user-записи `1dc004eb`, не предок. В chain не попадает.

Итог: 470 записей физически в файле, но **недостижимы** для backtrace. И для нашего Timeline, и для Claude CLI который тоже строит свой контекст по chain.

### Диагностика

Первое что проверять при отчёте "история резко обрезалась после Escape":
```bash
grep -oE '"uuid":"[^"]+"' file.jsonl | sort | uniq -c | sort -rn | head -5
```
Если есть UUID встречающийся `> 1` раз — это replay duplicate, не chain break и не corruption.

**Подтверждающий маркер:** все дубликаты имеют **одинаковый `promptId`** в копии (но разные в оригиналах). Это однозначный сигнал что они инжектированы одним внутренним resume'ом CLI, а не случайной коллизией.

**Ловушка диагностики:** active chain через backtrace **может казаться целой** (1032 записи, доходит до root, нет BREAK логов). Это потому что backtrace следует за дубликатами и собирает chain через них, минуя реальную работу. Проверять нужно **количество real user-сообщений** в active chain — если их кратно меньше чем ты помнишь, это симптом replay даже без видимых break'ов.

### Восстановление

Truncate файл до **первого дубликата** (его _idx ≥ позиции реплея):

```python
seen = {}
for i, rec in enumerate(records):
    uid = rec.get('uuid')
    if uid:
        if uid in seen:
            # truncate at i (drop the replay copy and everything after)
            truncate_at = i
            break
        seen[uid] = i
```

После truncate активная ветка снова целая, `claude --resume` поднимает корректный контекст.

### Отброшенные подходы

1. **«Это compact / DAG fork / proxy crash»** — все три не подошли. У compact `logicalParentUuid`, у fork разные `sessionId`, у proxy crash phantom UUID *отсутствует* в файле. Здесь UUID **есть в файле дважды**.
2. **Stub-записи** (как для proxy crash) — не помогут: проблема не в `null` на месте записи, а в том что Map заменяет первый экземпляр вторым. Нужен truncate.
3. **Дедуп в backtrace** (выбирать более ранний экземпляр UUID) — починит наш Timeline, но Claude CLI всё равно увидит обрезанный chain. Поэтому фиксить нужно в JSONL, не в backtrace.

### Версия

Воспроизводилось на Claude Code CLI **v2.1.119**. В более ранних версиях после Escape поток рвался чисто, replay не происходил. Нет известных версий где это уже починено.
