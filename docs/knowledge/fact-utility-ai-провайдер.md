# Fact: провайдер utility-вызовов AI

Utility-вызовы — это короткие служебные обращения к модели, которые приложение делает само, без участия вкладки Claude/Codex: сообщение Git-коммита, название вкладки, название Run After, пересказ промпта для Timeline, тема отложенной задачи, описание сессии в InfoPanel, заголовок свёрнутого блока AI Paste. Все они ходят через одного провайдера, выбранного константой `UTILITY_AI_PROVIDER` в `shared/utility-ai-provider.cjs` (`'openai'` | `'gemini'`). С 03.11.2026 это OpenAI: лимиты Gemini у пользователя недоступны, вызовы возвращали `There are issues with your billing account`.

Модуль общий для main и renderer, потому что обе стороны делают такие вызовы: сообщение коммита — из `ipc/git.js`, остальное — из `utils/generateTabTitle.ts`. Разъехавшиеся копии дали бы разного провайдера у соседних строк одной таблицы статистики. Пара `.cjs` + `.mjs`-реэкспорт повторяет принятый в проекте приём (`shared/tab-title-prompt.*`, `shared/codex-model-catalog.*`).

## Что НЕ входит

AI-Rewind (`rewind`) и группировка Timeline (`timeline-grouping`) остаются на Gemini по решению пользователя 03.11.2026. В renderer границу задаёт флаг `useUtilityProvider` у `generateTitleFromPromptWithConfig`: без него вызов идёт прежним путём Gemini, и именно так вызывается `generateTimelineActionLabelFromPrompt`. Мини-оркестратор (`mini-orchestrator-review`) не переносится: он использует Gemini-специфичный tool-calling с сохранением `thoughtSignature` и точного `Content`, этот контракт к Chat Completions не сводится. Семантический индекс (`ipc/semantic-search.js`) — embeddings `gemini-embedding-001` с размерностью 768; смена провайдера означает пересчёт всей базы `.semantic-index.json`, а не замену строки. `run-after-loop` вообще не API-вызов: текст исполняет агент своей вкладки.

Встроенные промпты `research`, `compact`, `adopt` в журнале вызовов не появлялись ни разу и API не вызывают — это текстовые вставки для контекстного меню, трогать их нечем.

## Сохранённая модель принадлежит провайдеру

Главная ловушка переключения. В таблице `ai_prompts` у всех utility-записей уже лежат модели Gemini, выбранные пользователем: они старше любого дефолта в коде и без проверки уехали бы в OpenAI как имя модели, вернув `model not found`. Поэтому `resolveUtilityAIModel` заменяет модель чужого провайдера на его default и сообщает об этом полем `replacedModel`; в журнал `logAIPromptCall` и в консоль пишется фактически вызванная модель, не та, что в настройках. Обратная сторона тоже проверяется: при возврате на Gemini модель OpenAI не уедет туда. Сохранённое значение пользовательское и остаётся в базе — переключение провайдера его не переписывает.

Default для OpenAI — `gpt-5-nano`. Он выбран по цене, а не по новизне: $0.05 за 1M входных и $0.40 за 1M выходных против $0.25/$1.50 у прежнего `gemini-3.1-flash-lite` (проверено 03.11.2026). Первая версия этой правки ставила `gpt-5.4-mini` ($0.75/$4.50) — он отвечает корректно, но для утилитарных задач дороже того Gemini, который заменял, то есть переключение делало расход хуже. При выборе модели для utility-задачи цена важнее качества: это 2–5 слов заголовка, а не рассуждение.

## Минимальный уровень размышления зависит от модели

Уровень в Settings общий для провайдеров (`NONE|LOW|MEDIUM|HIGH`) и переносится как есть, но перевод `NONE` в `reasoning_effort` различается: `gpt-5-nano` и `gpt-5-mini` отвергают `none` (`Supported values are: minimal, low, medium, high`), а `gpt-5.4-mini` и `gpt-6-luna` отвергают `minimal`. Поэтому `openAIEffortForModel` принимает модель вторым аргументом; единая для всех таблица ломала бы половину вызовов. Неизвестная модель получает `minimal` как более широко поддержанный, неизвестный уровень не отправляется вовсе, а не подменяется догадкой.

## Токены в статистике считаются по-разному

У Gemini `candidatesTokenCount` не включает размышление, у OpenAI `completion_tokens` включает. Settings → AI → Статистика показывает четыре колонки `in / out / think / Σ`, и если записать `completion_tokens` в `out` как есть, рассуждение посчитается дважды, а сумма колонок разойдётся с `Σ`. Поэтому для OpenAI видимый ответ считается как `completion_tokens − reasoning_tokens` (не ниже нуля), а `Σ` берётся из `total_tokens` либо считается сложением. Проверяет это `renderer/utils/utilityAIUsage.test.mjs` на реальных функциях модуля.

Пустой текст при `finish_reason: 'length'` означает, что бюджет вывода ушёл в рассуждение. Это ошибка, а не успешный пустой ответ: иначе Generate запишет пустое сообщение коммита, а вкладка — пустой заголовок. Оба пути возвращают в этом случае отказ с числом reasoning-токенов в тексте ошибки.

Красные карточки в истории вызовов и нули в колонках — это записи со `status: 'error'`, то есть отказы провайдера, а не нулевой расход. Описание сессии (`description`) до 03.11.2026 вообще не попадало в статистику: в InfoPanel была своя копия `fetch` без вызова `ai-prompts:log-call`. Теперь оно идёт общим путём и логируется как остальные.

## Выбор модели в Settings

Для utility-промптов чипы моделей показывают модели текущего провайдера (`constants/utilityModels.ts`), для остальных — прежний список Gemini. Набор OpenAI ограничен дешёвыми моделями, пригодными для коротких служебных задач: Nano 5, Luna 6, Nano 5.4, Mini 5. Тип `AIModel` расширен до объединения id обоих провайдеров, потому что сохранённое значение переживает смену провайдера.

Ключ — `OPENAI_API_KEY` (dev `.env`, packaged `~/.noted-terminal/.env`), уходит в заголовок `Authorization`, не в URL. В renderer он читается через IPC `settings:get-openai-api-key` и не встраивается в сборку — тот же порядок, что у `GEMINI_API_KEY`.

Цепочка запасных моделей в `generateAITitle.ts` удалена. Она перебирала `gemini-2.0-*` при 429 в поисках свободной бесплатной квоты; у платного ключа 429 означает реальный лимит аккаунта, и следующая модель упрётся в него же, поэтому остался один вызов и локальный fallback `paste text [N]`.
