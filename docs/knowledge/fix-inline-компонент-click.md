# Fix: Inline-defined компонент → trusted click молча проглатывается

Симптом для пользователя — «кнопка не реагирует на клик», иногда «работает каждый второй раз», без единой ошибки в консоли. Hover работает, focus работает, визуально кнопка живая. Соседние прямые `<button>` в JSX продолжают кликаться нормально — что особенно сбивает с толку, потому что выглядит как «эти клик ловят, эти нет, почему?».

Программный invoke handler'а через React fiber (`__reactProps$.onClick()`) срабатывает. Программный клик через CDP/MCP — тот же результат «handler не вызвался, но pointerdown/pointerup дошли». Window-listener показывает: `pointerdown`, `pointerup`, `mousedown`, `mouseup` приходят к окну, **`click` отсутствует**.

## Причина

Если компонент-функция объявлен внутри тела другого компонента (`const Chip = (props) => <button .../>` прямо внутри `function Parent() { ... }`), React на каждом рендере родителя видит новый component type — новая ссылка на функцию — и пересоздаёт под него новый DOM-node. Реквизиты и onClick переносятся корректно, визуально ничего не меняется, но identity DOM-ноды между рендерами не сохраняется.

Это ломает trusted click events. Браузер генерирует синтетический `click` только если `pointerdown` и `pointerup` пришли на тот же DOM-node без drag-смещения. Между этими двумя событиями родитель может ре-рендериться (поллинг, hover-state, любая Zustand-подписка) — `pointerdown` приходит на старую `<button>`, та заменяется новой DOM-нодой при ре-рендере, `pointerup` приходит на новую ноду → click не выстреливает. React fiber хранит свежий handler, поэтому программный вызов работает; реальный пользовательский клик — нет.

Правило одно: никогда не определяй компонент-функцию внутри body другого компонента. Выноси на module-scope; либо мемоизируй через `useMemo` (для редкого случая когда компонент обязан замыкать локальные значения, но prop-проброс почти всегда чище). Правило важно даже когда сам компонент простой (`<button>` без своего state) — DOM-node identity всё равно теряется.

Отдельный класс симптома — flicker фокуса: text input внутри inline-компонента теряет фокус после каждого keystroke, потому что React пересоздаёт `<input>` ноду. Та же причина. Если ловишь баг «инпут теряет фокус каждый ввод», смотри в иерархии родителей нет ли inline-определения компонента.

## В custom-terminal

`ChipText` внутри `InfoPanel`-render — клики по `text · thinking · read · edit · bash · mcp` молча проглатывались. User и Claude иконки работали потому что были прямыми `<button>` в JSX, не через inline-компонент. Фикс: вынести `ChipText` + константы цветов `CHIP_ON`/`CHIP_OFF` на module-scope перед `function InfoPanel()`. Воспроизведение бага через MCP подтвердило: `pointerdown`/`pointerup` доходили, но `elementFromPoint` сразу после `pointerdown` возвращал **другой** `<button>` instance на тех же координатах — DOM-нода успела пересоздаться.

См. `src/renderer/components/Workspace/panels/InfoPanel.tsx::ChipText` (module-scope, с inline-комментарием почему именно так), `fact-clipboard-tools.md::Markers row`.
