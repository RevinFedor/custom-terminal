# Fact: Git-коммиты проекта

Git-интеграция в workspace — это project-level control, а не tab-level инструмент. Постоянная поверхность в toolbar показывает только то, что нужно держать в поле зрения всегда: текущую ветку и количество незакоммиченных файлов. Всё остальное живёт в раскрытой панели по клику: список изменённых файлов, история, выбор ветки, генерация commit message, локальный commit и remote-действия.

## Toolbar contract

Git-кнопка стоит в самом правом краю project toolbar, после Docs/Copy Sessions/usage-чипов. Она не появляется вне Git-репозитория и не занимает toolbar в проектах без `.git`. Лицо кнопки — `branch + changed count`; clean-state остаётся коротким `branch · clean`. Это сделано по тому же принципу, что usage-чипы: постоянная полоса показывает статус, а не полный workflow. Подробный переносимый принцип — `methodology/переносимый-дизайн.md::Постоянная панель показывает статус, не workflow`.

Панель открывается рядом с кнопкой, а не из центра окна: Git-действия относятся к проекту и текущему рабочему дереву, поэтому пользователь должен воспринимать её как расширение toolbar. Панель закреплена к правому верхнему углу триггера и ресайзится влево/вниз; размер сохраняется, чтобы переключение Changes/History не меняло высоту и не дёргало layout. Settings-шестерёнка находится внутри самой Git-панели, потому что настройки влияют только на этот commit workflow; в маленьком toolbar-чипе остаётся только статус.

## Repository selector

Git-панель привязана к текущему проекту, но выбранный Git-репозиторий внутри неё может быть другим: монорепозиторий и вложенные `.git`-папки живут в одном workspace. По умолчанию открывается репозиторий текущего проекта; если пользователь уже выбирал другой repo для этого проекта, выбор восстанавливается из project-scoped state. Это важно не оптимизировать в «всегда project path»: иначе пользователь в монорепе каждый раз будет заново искать нужный пакет.

Repo-select имеет две вкладки. `Repos` — общий список с поиском; репозиторий текущего проекта всегда первым и отмечен только home-иконкой слева, без отдельного текста «pinned». `This Project` — избранные именно этого проекта: добавление идёт через compact context-menu на строке repo, порядок меняется drag-handle'ом справа и сохраняется вместе с состоянием панели. Последняя открытая вкладка селекта тоже сохраняется, потому что для частого переключения между несколькими вложенными repo вкладка избранного становится основным рабочим входом.

## Commit workflow

Changes-tab показывает изменённые файлы слева и diff-preview выбранного файла справа, как source-control GUI, а не как простой checklist. Чекбокс меняет набор файлов для commit/generate; клик по строке открывает файл в правом preview. Эти жесты нельзя объединять: пользователь ожидает, что клик по файлу читает изменения, а не молча меняет состав commit'а.

В списке файлов статус показывается компактной иконкой справа: зелёный плюс для added/untracked, жёлтая точка для modified/renamed/other, красный минус для deleted. Сырые porcelain-коды (`M`, `??`) не выводятся в начале строки: они полезны для Git CLI, но в GUI читаются как мусор, особенно рядом с чекбоксом.

Локальный commit работает без GitHub auth: remote-доступ нужен только для push/fetch/publish. При commit выбранных файлов нельзя просто сделать `git add <paths>` и затем обычный `git commit`, потому что уже заранее staged-файлы из другого workflow тоже попали бы в commit. Commit должен фиксировать только выбранные пути; заранее staged unrelated-файлы остаются staged после операции.

History-tab — read-only журнал последних commit'ов. Branch dropdown переключает локальные ветки из той же панели; push-кнопка сделана split-button'ом: основное действие — `Push` или `Publish` в зависимости от upstream, дополнительное меню содержит `Fetch origin`.

## AI commit message

Generate вызывает текущую Claude API-конфигурацию из Docs/API settings и пишет вызов в общий журнал AI prompt usage как `git-commit-message`. Это не billing-источник и не usage-chip: статистика нужна, чтобы видеть модель, токены, ошибки и источник utility-вызова рядом с другими metadata prompt'ами.

Prompt policy: если toggle `Docs-only AI context` включён и среди выбранных изменений есть `docs/`, AI получает только изменённые docs-файлы. Если toggle выключен или docs-изменений нет, AI получает выбранные изменения целиком с caps/truncation. Причина — commit message для документационного прохода должен описывать именно изменение документации, а не шум от параллельных файлов в рабочем дереве.

## Remote auth recovery

Push/fetch ошибки авторизации не запускают собственный login-flow в Noted Terminal. HTTPS token, SSH key, credential helper и GitHub account state слишком разные, чтобы воспроизводить GitHub Desktop внутри toolbar-панели. Правильная реакция — общий persistent toast «GitHub не принял доступ» с действием `GitHub Desktop`; клик открывает GitHub Desktop на текущем project path, где пользователь логинится штатным способом.

Локальные действия при этом не блокируются remote auth. Если GitHub не принимает push, пользователь всё равно может продолжать делать локальные commit'ы и вернуться к publish позже.
