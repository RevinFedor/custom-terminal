# Feature: CLAUDE.md mirror (AGENTS.md / GEMINI.md auto-copy)

## Intro
Один CLAUDE.md в корне проекта — единственный источник истины. Когда тогл «Зеркала CLAUDE.md» в Settings → Системные включён, main процесс автоматически копирует CLAUDE.md в `./AGENTS.md` и `./GEMINI.md` тех же проектов и держит их в синхроне: правка CLAUDE.md → mirror'ы перезатираются, правка mirror'ов → mirror перезатирается копией источника.

Watcher живёт в `src/main/ipc/claude-md-mirror.js`. Wiring renderer'а — `App.tsx` блок «CLAUDE.md mirror watchers», UI — `SettingsModal.tsx::ClaudeMdMirrorBlock` (внутри `activeTab === 'colors'`).

## User flow
- Settings (`Cmd+,`) → таб «Системные» → секция «Зеркала CLAUDE.md» (выше «Семантическая индексация»).
- Источник `./CLAUDE.md` показывает ✓/✕ и размер.
- Toggle справа от заголовка секции (default OFF).
- Под источником две строки `./AGENTS.md` и `./GEMINI.md` — каждая со статусом ✓ в синхроне / ⚠ расходится / ○ отсутствует, временем последней записи и (если есть рассинхрон) кнопкой «Создать сейчас» / «Перезаписать».
- При OFF файлы независимы, ничего не пишется.

## Источник истины и BANNER

Каждое зеркало начинается с одной HTML-комментарной строки:

```
<!-- AUTOGENERATED MIRROR of CLAUDE.md. Source of truth is CLAUDE.md — edits to this file will be overwritten. -->

<содержимое CLAUDE.md>
```

Banner — HTML-комментарий, в rendered markdown (GitHub) невидим. Это и user-visible warning, и stable marker который позволяет main сравнивать «что на диске» vs «что должно быть» по equal-байт сравнению, без отдельной мета-таблицы. `computeStatus` строит `expected = BANNER + '\n\n' + sourceContent` и сравнивает с тем что лежит на диске → флаг `inSync`.

## Watcher lifecycle

Один `fs.watch` на корень каждого открытого проекта (точно как у `semantic-index-status.js`). Watcher запускается из `App.tsx` параллельно semantic-index watcher'у по тем же сигналам (`useWorkspaceStore.subscribe + useProjectsStore.subscribe`), `mirror:watch` IPC при добавлении проекта в `openProjects`, `mirror:unwatch` при удалении.

Watcher запущен ВСЕГДА, даже если тогл OFF — без этого нельзя показывать актуальный статус в Settings, и при включении тогла пришлось бы ждать первого fs-события. При OFF watcher только пересчитывает status и пушит в renderer, write skip'ается (`if (!mirrorEnabled) return` в `syncMirrors`).

## Internal-write loop guard

Главный шрам fs.watch паттернов: наша запись в `AGENTS.md` сама вызовет `fs.watch` event на этом же файле, который опять триггернет `syncMirrors` → loop. Решение — `state.ignoreUntil: Map<absPath, expiresAt>`. Перед каждым `fs.writeFileSync` зовём `markInternalWrite(state, path)` который ставит `path → now + 1500ms`. Watcher-обработчик первым делом проверяет `isInternalWrite(state, abs)` и игнорит event если TTL не истёк.

TTL = 1500ms потому что на macOS fs.watch может выстрелить несколько раз на один write (open, write, close — отдельные события, плюс atomicrename'ы редактров типа vim/sublime). Меньше — рискуем пропустить guard на медленных дисках. Больше — не страшно: пользователь физически не успеет отредактировать mirror руками за 1.5с.

## Debounce

300ms перед `syncMirrors` (та же константа что и у semantic-index). Без debounce редакторы типа VSCode (sync write + atomic rename) триггерят 2-3 события подряд → 2-3 ребилда → лишние writes. С debounce — один write в покое.

## Persistence тогла

`claudeMdMirrorEnabled` в SQLite через `app:setState` ключ `claudeMdMirrorEnabled`, зеркало в localStorage `noted-terminal-claude-md-mirror` для синхронного boot read. Та же причина что у `defaultClaudeEffort` и `freePortsBeforeStart` — см. `fix-localstorage-origin.md`: vite-port в dev меняется → разный origin → localStorage пустой. SQLite в main process origin-independent.

Main процесс hydrate'ит флаг из SQLite на старте (`projectManager.db.getAppState('claudeMdMirrorEnabled')`), чтобы знать тогл до первого IPC из renderer'а. После переключения тогла renderer вызывает `mirror:set-enabled` и сразу же пишет тот же ключ через `app:setState` — оба пути ведут в одну строку в `app_state`, чтобы main и renderer не разъезжались.

## Edge-кейсы

- **CLAUDE.md удалён** → `syncMirrors` рано выходит (`src === null`), mirror'ы не трогаются. В UI источник помечен ✕. Когда файл появится — watcher fs.watch на корне ловит rename event, debounce → sync.
- **Mirror удалён вручную** → отображается «отсутствует ○», кнопка «Создать сейчас» вручную дёргает `mirror:create-now`. Альтернативно — любая правка CLAUDE.md его пересоздаст.
- **Mirror отредактировали в редакторе** → watcher fires, debounce → `syncMirrors` сравнивает on-disk с expected, перезатирает копией. Юзер видит что его правка пропала — это и есть смысл "источник истины".
- **Тогл ON при существующем «чужом» AGENTS.md/GEMINI.md** → при первом sync они будут перезатёрты. UI до включения тогла показывает «⚠ расходится» — пользователь видит несовпадение и может перенести нужное в CLAUDE.md прежде чем включать.
- **`npm run build:install`** → SQLite сохраняется (она вне `dist/`), тогл переживает. На первом запуске нового билда watcher навешивается на все открытые проекты, делает initial sync и пушит статус.

## Scope

Только `./CLAUDE.md` в корне проекта. `packages/openclaw/CLAUDE.md` и любые другие вложенные CLAUDE.md НЕ трогаются — это submodule/sibling-пакет со своим ownership'ом. Если когда-то понадобится зеркалить вложенные — добавится отдельная рекурсивная walk (но это будет другой тогл).

## IPC contract

| Channel | Direction | Payload | Назначение |
|---|---|---|---|
| `mirror:watch` | renderer → main | `{ projectId, projectPath }` | Старт fs.watch + initial sync + push status |
| `mirror:unwatch` | renderer → main | `{ projectId }` | Stop watcher, очистить state |
| `mirror:get-status` | renderer → main | `{ projectId }` | Pull-режим: вернуть status сейчас |
| `mirror:set-enabled` | renderer → main | `{ enabled }` | Переключить глобальный флаг, sync всех проектов |
| `mirror:create-now` | renderer → main | `{ projectId }` | Принудительная перезапись mirror'ов для проекта |
| `mirror:status` | main → renderer (push) | `{ projectId, enabled, source, mirrors }` | Push каждый раз когда что-то изменилось |

`mirrors[i]` = `{ path, name, exists, sizeBytes, mtime, inSync, lastWriteAt }`. `lastWriteAt` — момент когда main сам писал файл (полезно для UI «обновлено HH:MM»); `mtime` — fs mtime (на случай если файл правили снаружи).
