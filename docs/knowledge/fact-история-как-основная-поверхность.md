# History как основная поверхность AI-вкладки

## Зачем изменили роли

Для Claude/Codex PTY-вкладок основная работа идёт с ходами диалога, status, Send/Stop/Resume/Rewind, а не с ANSI-экраном CLI. Поэтому History теперь занимает центр рабочего места, а raw-терминал стал полноценным escape hatch по кнопке. Это не просто перестановка вёрстки: History должна сохранить все сценарии живого TUI, а терминал — весь буфер, focus, search и ввод.

Режим включён для обычных PTY-вкладок Claude и Codex, включая новую вкладку без ещё созданного session ID. Не распространять его на Gemini, Claude SDK, browser и file-tab просто ради симметрии. У Gemini нет парного History composer/runtime-контракта, а остальные типы вкладок вообще имеют другую primary surface; скрыть их до появления этого контракта было бы downgrade.

## Контракт поверхностей

- History не имеет панельной шапки `History`, reset-width, крестика и постоянной кнопки поиска. `Cmd+F` открывает временную строку поиска над историей.
- Единый control слева над input не превращает устойчивые `ready/busy/stopped` в текстовые статусы: они читаются по цветной SVG-иконке terminal и hover-описанию, а во время `busy` вокруг неё идёт круговой loader. Текст появляется только у переходов с самостоятельным смыслом — STARTING/STOPPING/REWINDING/UPDATING/interrupted/error. Отдельные BUSY + THINKING плашки запрещены: один lifecycle не должен занимать две строки.
- Клик по status-control открывает и сворачивает floating xterm; белая рамка всего control означает, что окно показано. Описание открывается сразу по hover, правый клик копирует title, description, полные session ID и tab ID для логов.
- Когда terminal открыт, `Cmd+F` принадлежит terminal search; когда свёрнут — History search. В titlebar terminal нет отдельной search-кнопки. Два global capture-listener не должны открывать оба инпута.
- Обычные user/assistant-блоки показывают контент без повторяющейся строки `CODEX/CLAUDE · время · message id`: агент уже понятен из вкладки, а техническая строка перед каждым сообщением разрушает сканирование. Правый клик по пустой части блока открывает native action `Copy ID and details`; правый клик по самому тексту не перехватывается, чтобы сохранить системную работу с выделением и копированием.
- Под durable user-блоком зарезервирована компактная строка действий Copy/Rewind, которая проявляется по hover или keyboard-focus. Она остаётся в геометрии строки даже когда визуально скрыта, иначе Virtuoso переизмеряет сообщение при каждом наведении. Copy берёт только prompt; Rewind передаёт raw UUID в Timeline и проходит тот же runtime/boundary guard, что контекстное меню точки, а не поддерживает второй rollback-flow.
- Composer по умолчанию начинает с трёх строк и растёт по переносу текста до пользовательского предела в 20 строк. И начальная высота, и предел настраиваются отдельно в `Settings → Размеры → AI-интерфейс → Поле ввода`; предел никогда не может стать меньше начальной высоты. После него высота фиксируется и появляется тонкий внутренний scrollbar, browser resize-handle намеренно отсутствует. Шрифт transcript/tool-блоков задаётся отдельно в «История», шрифт набираемого текста — в «Поле ввода».
- Сохранённый prompt из picker всегда становится prompt-чипом независимо от длины: происхождение нужно для узнаваемого label и повторный выбор той же вариации обновляет существующий чип по stable source key. Ручной text paste становится paste-чипом только когда длиннее настраиваемого порога (по умолчанию 800 символов); одинаковые paste-чипы не дедуплицируются, потому что повторная вставка может быть намеренной.
- Чип — обратимая проекция текста: после вставки он остаётся свёрнутым и показывает только заголовок. Раскрытие происходит только по явному клику, выводит содержимое и число символов отдельным overlay над composer и не меняет высоту History; отдельная стрелка возвращает текст в текущую selection/caret, удаление не подменяется распаковкой. Чипы живут в той же верхней строке, что terminal-status, после визуального разделителя. Владелец draft — tab, а его состояние является тройкой `raw text + chips + image refs`; дописывание диктовки, Task Plan или Replay сохраняет остальные части, полная замена/Rewind очищает их явно.
- При Send prompt-чипы идут первыми обычным prompt-текстом, paste-чипы — следующими в `<pasted_content>`, редактируемый текст — последним. Image-marker materialize применяется к raw textarea до этой сериализации: литерал `[Image #1]` внутри opaque-чипа не является ссылкой на attachment composer'а и не должен присвоить или удалить чужой ref. Snapshot для rollback хранит raw text, chips и images вместе. Ошибка до Enter возвращает его точно, а если пользователь уже начал следующий draft — ставит прежний текст перед новым, перенумеровывает конфликтующие image-marker и сохраняет оба набора чипов. Ответ `{submitted:true}` уже передал ownership терминалу даже при поздней ошибке подтверждения: такой prompt получает предупреждение, но не восстанавливается и не отправляется повторно.
- History и SDK используют одну stateless-оболочку карточки: она задаёт геометрию status, чипов, preview и input-slot, но не владеет draft, отправкой, очередью, rollback или lifecycle. Эти действия остаются у PTY History и SDK runtime соответственно; объединять их ради визуального сходства запрещено. Правой колонки, action-footer и model/session footer внутри карточки нет.
- Простой `Enter` и `Cmd+Enter` отправляют, `Shift+Enter` вставляет новую строку. В остановленной вкладке это не двухшаговый `Start/Resume`, а одно submit-намерение: History фиксирует нажатый snapshot, показывает `STARTING`, через общий scenario layer запускает или возобновляет агента, ждёт authoritative input-ready и отправляет snapshot ровно один раз. Ошибка до реального submit возвращает тот же draft; пользователь не нажимает Enter повторно. Видимые Mic, Enter, terminal → History и остановка текущего ответа живут в нижней control bar и вызывают канонические History-действия, а не пишут управляющие байты в скрытый xterm. `Escape` и красный `^C` прерывают только текущий ответ; единственный lifecycle-control Claude/Codex отвечает за Start/Resume и полное завершение процесса. Доступность нижних действий публикует сам History composer, поэтому переход, вопрос, Rewind или неготовое изображение одновременно блокируют и принимающую сторону, и кнопку.
- Send и Stop сериализуются как пользовательские намерения, но не подменяют друг друга. Если Stop приходит во время атомарного auto-start/send, его нельзя отбросить как «действие уже выполняется» и нельзя послать `Ctrl+C` посередине paste: History удерживает `STOPPING`, завершает handoff зафиксированного prompt и сразу выполняет ровно один отложенный Stop. Очередь принадлежит tab-scoped scenario owner, а не смонтированному React-компоненту, поэтому переключение A→B до завершения Send не отменяет Stop A. Так сообщение остаётся доставленным, а turn действительно прерывается без краткого возврата в `busy/starting`.
- Правый клик по composer открывает кастомный первый уровень `Insert Prompt / Scripts` в той же визуальной грамматике, что Opt+V. Оба пути вставляют в tab-scoped History draft, а не в скрытый xterm. Скрипт вставляется как редактируемый текст без `CR` и без запуска; рабочая директория берётся у живого PTY с fallback на cwd вкладки.
- `Cmd+V` с bitmap вставляет короткий синий `[Image #N] ` с одним завершающим пробелом и кареткой после него, а durable файл хранится отдельно от редактируемого текста. Подсветка composer меняет только цвет marker: иной font-weight рассинхронизирует метрики прозрачной textarea и видимого слоя, из-за чего каретка визуально оказывается внутри `#N`. Marker и ref принадлежат tab-scoped draft вместе: переключение вкладки их не теряет, полное удаление marker освобождает только его ref, повреждённый marker сохраняет ref для ремонта и блокирует отправку. После Send тот же marker или materialized `[imagePath: …]` остаётся синим внутри user-блока: commit не должен превращать узнаваемое вложение в обычный текст.
- Пока bitmap сохраняется, composer показывает `[Image saving…]`; Send и перенос в Run After запрещены. Перед Send файл заново проверяется, после чего marker раскрывается в transport path. Для транспорта крайние whitespace обрезаются, но compare-and-clear сверяет неизменённый исходный draft: сравнение raw draft с trimmed payload ложно принимает завершающий перенос за новую пользовательскую правку и оставляет уже отправленный текст в input. Если пользователь действительно успел допечатать или заменить вложение во время асинхронной проверки, отправляется нажатый snapshot, а более новый draft не очищается.

## Быстрый возврат и раскрытие блоков

При возврате A → B → A History сразу показывает последний ограниченный snapshot A, не заменяя уже известные строки экраном `Loading`. В фоне main проверяет durable revision источника; неизменившийся transcript не проходит повторный parse/projection/IPC. Старый ответ первого открытия A не имеет права примениться к новому A после промежуточного B: каждая привязка owner получает новое поколение.

Durable cache хранит сырые server rows, а локальные queued/sent/rewind строки и временные suppression — отдельный малый overlay. Локальный prompt с первого кадра выглядит тем же правым user-блоком, что и сохранённая реплика; `SENDING / QUEUED / SENT / FAILED` меняют только status-badge, а не геометрию сообщения. После `SENT` нет временного удаления: overlay живёт до появления соответствующей durable user-записи, иначе задержка JSONL превращалась бы в исчезнувшее уже отправленное сообщение. Только доказанные `cancelled/failed` имеют короткий срок показа. Rewind-operation остаётся системным событием, а восстановленный prompt — обычным правым user-блоком.

Post-Enter audit timeout означает «ещё не согласовано», а не delivery failure. Пустой terminal draft после Stop также нормален, если TUI уже принял prompt, и сам по себе не разрешает cancellation/suppression. Durable UUID всегда выигрывает у локальной эвристики; suppress поздней строки допустим только по точной identity доказанно отменённой ветки.

Prompt-чипы не кодируются служебными тегами в тексте, который получает агент. Их presentation хранится отдельным SQLite-sidecar и привязывается к durable user UUID только после post-Enter proof. Токен sidecar входит в revision History, поэтому запись presentation во время асинхронного чтения не может вернуть stale cache; Rewind/fork переносит sidecar только после точного child proof. Неоднозначность fail-closed оставляет обычный текст, а не приписывает чужому сообщению чип.

Presentation-фильтр нельзя записывать как durable snapshot: иначе отменённый prompt останется скрытым после истечения suppression, пока файл физически не изменится. Лимиты и точный контракт revision описаны в `fact-transcript-сервис.md`.

Первый кадр привязан к одной атомарной тройке `owner + rows + loading`. При A → B нельзя сначала опубликовать owner B, а строки B добавить следующим render: промежуточное `owner=B, rows=[]` выглядит как необъяснимая пустота без loader. Пока committed rows ещё принадлежат A, B остаётся в loading; owner и строки B меняются вместе.

Готовые данные и рассчитанный диапазон виртуализатора ещё не доказывают, что пользователь увидел строку. На холодном owner loader снимается только после появления реальной DOM-строки и следующего paint; иначе между `rangeChanged` и отрисовкой тяжёлого элемента остаётся белый кадр. Paint-probe принадлежит точному owner+generation и отменяется при cleanup: поздний кадр закрытой A не может снять loader новой B. Exact cache-hit уже имеет ранее нарисованную проекцию и не проходит этот cold gate.

Primary composer закреплён отдельным absolute-слоем у нижней границы History, а не является flex-соседом, который уменьшает viewport списка при каждой новой строке. Его внешний слой прозрачен, а видимая карточка повторяет SDK inset: 16 px по бокам и 4 px снизу. Virtuoso остаётся одного размера; его Footer резервирует ровно измеренную высоту всего слоя с inset, поэтому последнее сообщение достижимо. Если пользователь читает середину, рост input не меняет `scrollTop`; если он уже у хвоста, список догоняет новый реальный низ.

При раскрытии Thinking/tool/MCP/Edit/Compact/Subagent History не прыгает к глобальному низу и не сохраняет старую верхнюю координату блока. После того как виртуализатор измерил новую высоту строки, список сдвигается только на положительный overflow нижней границы раскрытого блока; если блок и так помещается, scroll не меняется.

Раскрытый code/diff/output не получает колесо только потому, что курсор оказался над ним. До клика wheel прокручивает общую History; клик по реально переполненному body передаёт вложенному scroll ownership и делает существующую левую rail светлее. Верхний и нижний край внутреннего scroll не снимают ownership: дополнительные прокрутки остаются поглощены блоком, пока указатель внутри него. Ownership возвращается наружу только по клику или wheel вне активного body либо при отдельном scroll общей History. Listener живёт на одном native non-passive capture уровне Virtuoso: активная внутренняя ветка обязана отменить default и propagation, иначе колесо цепочкой доедет до родителя.

Standalone tool-call уже является отдельной строкой transcript, поэтому не должен одновременно наследовать вертикальный padding обычного assistant-сообщения и полные внешние margins карточки из общего renderer-пакета. Пользовательский симптом — вокруг `BASH ls …` появляется почти пустая строка сверху и снизу при нормальных данных rollout. Уплотнение scoped только внутри History: общий пакет используют другие поверхности с другой композицией, и глобальная правка изменила бы их без доказанной проблемы.

Edit/diff получает номера строк только из события, которое авторитетно описывает выполненное изменение: у Codex это exact-match `patch_apply_end.changes[].unified_diff`, у Claude — exact tool-result `structuredPatch`. Один общий `startLine`, повторный поиск фрагмента в уже изменённом файле и порядковые `1…N` дают правдоподобные, но ложные координаты. Multi-hunk передаётся как отдельные old/new диапазоны; при отсутствии или неоднозначности proof gutter остаётся пустым.

Production-цепочка переключения вкладок диагностируется через `[HistoryHandoff] SURFACE_OWNER`, `LOADER_VISIBLE/LOADER_HIDDEN`, `LOAD_START/LOAD_APPLY/LOAD_UNCHANGED/LOAD_STALE_DROP`, `CACHE_WRITE/CACHE_REJECT` и `SURFACE_PRESENTED`. Последний содержит owner/generation, cache hit/miss, число реально смонтированных DOM-строк и paint-proof, поэтому data-ready не маскируется под увиденную поверхность. Переход локального prompt в durable логируется отдельным `PROMPT_ADOPT` с local/handoff/server UUID, timestamps и match mode; одного `matched=true` недостаточно для разбора одинаковых prompt. В одной owner-цепочке есть короткие tab/session, digest полного owner, generation, cache age/rows/bytes и digest вытесненных owners. Это различает exact miss, новый writer/session в той же вкладке, LRU/oversize rejection, поздний ответ предыдущего поколения и blank между data-ready и paint.

## Единственный xterm и связанные слои

Floating-окно оборачивает тот же единственный `TerminalArea`; второй `TerminalArea`, новый React key или Portal для самого xterm запрещены. Закрытие меняет только presentation (`visibility`, `opacity`, `pointer-events`) и не меняет active/runtime lifecycle. Иначе сворачивание потеряет terminal buffer, PTY listeners, composer draft или фоновое управление из API/iOS.

Скрытый xterm продолжает быть текущим TUI и main/headless screen authority, но сам факт живого процесса не означает «на экране пустой composer». Перед History Send приложение различает composer, startup, model picker и native Rewind overlay; последние три оставляют History draft на месте и не получают Enter. Это короткая проверка режима прямо у границы записи, а не прежний долгий status/process/session preflight: обычный физический Enter пользователя по-прежнему сразу уходит в PTY.

Run After логически принадлежит AI-вкладке, а не видимому прямоугольнику xterm. Он продолжает жить внутри `Terminal`, но в primary-History рендерится через Portal в workspace-level host над History; нижняя граница host измеряется по controls, поэтому очередь не перекрывает input. Это сохраняет один store/lifecycle при скрытом terminal; кнопка History в rail скрыта как дубль уже основной поверхности. Task panel остаётся отдельным workspace-overlay.

У Run After два разных класса действий. Обычный Replay и `+grab` манипулируют тем input, который пользователь видит: в primary-History это tab-scoped History draft, причём Replay аппендит текст и не затирает уже набранное. `Cmd+Replay` и автоматический Run After остаются на общем подтверждаемом PTY scenario-path: переводить их через запись draft + синтетический клик Send нельзя, иначе появятся два владельца handoff и риск двойной отправки. Отдельная кнопка terminal → History в нижней control bar остаётся явным способом забрать draft именно из floating terminal; она доступна и во время BUSY, потому что читает отдельно набранный TUI draft и не вмешивается в текущий ответ. Stop, Rewind, pending question и другая незавершённая History-операция по-прежнему блокируют перенос.

Обычный `+grab` и Replay переносят text, chips и images одним изменением. Prompt-чип при возврате дедуплицируется по source key, paste-чип сохраняет каждое повторение, а chip-only item не добавляет разделительные пустые строки в уже набранный draft. Редактор очереди показывает те же чипы с preview / «вернуть в текст» / delete; title карточки остаётся presentation и никогда не становится скрытым payload. Если удалён последний чип из chip-only item, исчезает пустая запись целиком, а не отправляется её человекочитаемое название.

При обычном Replay изображение переезжает как semantic `[Image #N]` плюс отдельный durable ref; ID перенумеровываются относительно уже набранного draft. Длинный `[imagePath: …]` появляется только на границе Send. Для Codex transport затем создаёт native image slot через whitespace-free alias, Claude получает стабильную file-reference — одинаковое хранение не означает одинаковый native TUI transport.

Тот же ownership действует для внешнего ввода внутри вкладки: диктовка и другие composer-injection действия дописывают tab-scoped History draft, а не невидимый xterm. Enter после остановки диктовки вызывает канонический History Send, который уже владеет attachments, readiness и rollback; сырой `CR` в скрытый terminal отправил бы не тот текст, который пользователь видит.

Обычные `ready/busy/stopped` остаются проекцией существующего History runtime и меняют только цвет/loader terminal-иконки. Детальные startup/stopping/interrupted берутся из уже существующего lifecycle в `TerminalArea` и передаются как готовое presentation. Не создавать ещё один набор IPC listeners в status-row: два независимых вычисления одного lifecycle дадут спокойную иконку в History одновременно с LOADING в terminal overlay.

History Start/Resume не пишет launch-команду напрямую через `terminal:input`. Остановленный агент может оставлять обычный shell с незапущенным пользовательским текстом; поэтому History вызывает тот же main-side launch boundary, что control bar, aliases, auto-resume и внешний API. Boundary отменяет shell-строку только после свежего доказательства, что foreground-процесса нет, а затем атомарно запускает агент. History снимает interrupted-состояние лишь после ответа `accepted`; отказ оставляет Resume и исходный статус доступными, а не превращает попытку в ложный `STARTING`. Это не распространяется на Send в живой TUI — там terminal draft имеет отдельный ownership/preflight-контракт.

## Геометрия floating-окна

Окно перемещается за titlebar и меняется с четырёх сторон и четырёх углов. Каждая ручка двигает только схваченные границы; противоположные остаются на месте. Пределы: 30–80% ширины и 20–80% высоты рабочей зоны. Первоначальный максимум 60% оказался неочевидным: сохранённое окно уже стояло на лимите, поэтому drag верхней/нижней грани наружу выглядел сломанным, хотя pointer hit-test работал. Геометрия хранится в процентах, чтобы переживать другой размер окна.

Нижняя граница рабочей зоны floating terminal не фиксирована: `ResizeObserver` меряет реальную высоту status/composer, поэтому auto-grow input и AskUserQuestion поднимают нижний clamp окна. Сам viewport History при этом не сжимается — безопасное место под composer задаёт Footer spacer. После достижения предела скроллится input. В начале drag/resize нужно снимать фактический `getBoundingClientRect()` окна, а не доверять ref после async hydrate: иначе первый drag одновременно переместит и изменит размер. Preview обновляется не чаще одного `requestAnimationFrame`, persistence применяется один раз на `pointerup`.

## Что проверять при изменениях

- Открыть/свернуть terminal и убедиться, что DOM-rect и buffer сохранились, а hidden layer не забрал focus у History input.
- После fresh restore первый drag меняет только position; каждая из восьми resize-ручек сохраняет противоположные edges и clamp.
- Увеличить textarea до настроенного max-height: terminal stage должен уменьшиться, окно остаться выше controls, а следующий текст — прокручиваться внутри input без ручной resize-ручки.
- Прогнать `Cmd+F` в обоих режимах, trusted terminal input, нижний scroll-to-bottom, status copy и живой Run After. В titlebar остаётся только Hide; scroll появляется внизу лишь после прокрутки вверх. В Run After не должно остаться кнопки History, а обычные `+grab → Replay` должны перенести draft History → queue → History без фокуса скрытого xterm.
- Продиктовать текст, затем нажать Enter: сначала он должен появиться в видимом History input, затем уйти через History Send; скрытый terminal composer остаётся нетронутым.
- Проверить `Enter`, `Cmd+Enter`, `Shift+Enter`, нижние terminal → History / Enter / `^C` / Resume, ПКМ `Insert Prompt / Scripts` и Opt+V: вставка остаётся в History draft, выбранный скрипт не исполняется, а `^C`/Escape не убивают весь процесс.
- Вставить два bitmap подряд: получить `[Image #1]`/`[Image #2]`, переключить вкладку и вернуться, удалить один marker, затем прогнать `History → +grab → Replay → History`. Pending/damaged marker не должен покидать History; допечатанный во время проверки файла текст остаётся следующим draft.
- На длинной History раскрыть блок у нижнего края: его низ должен стать виден без прыжка к концу всей истории. Wheel над блоком до клика двигает History; после клика светлая rail показывает внутренний focus, а click-outside/outer scroll его снимает.
- Переключиться A → B → A: строки A должны быть видны в первом кадре без `Loading`, а фоновая проверка не должна вернуть старый ответ другой генерации. Между loader и строками не должно быть пустого кадра. Если loader появился, одна последовательность `SURFACE_OWNER → LOADER_* → LOAD_* → CACHE_*` должна объяснить точную причину.
- В остановленных Claude и Codex набрать уникальный текст в History и один раз нажать Enter: должен появиться `STARTING`, затем тот же prompt уходит после ready; второй Enter/ручной Resume не нужен, а ошибка до submit возвращает draft.
- Навести durable user prompt: Copy/Rewind появляются без сдвига соседних строк. Copy берёт только prompt, а Rewind на idle-вкладке даёт тот же preview/draft и lifecycle, что действие Timeline; во время busy должен быть видимый отказ.
- Увеличить composer в середине длинной History: видимое сообщение и `scrollTop` не меняются. Повторить у самого низа: хвост остаётся доступен над composer, floating terminal не перекрывает input.
- Между соседним текстом и standalone Bash/tool-call не должно быть «пустой строки» из сложившихся отступов; раскрытый output остаётся внутри измеренной строки и не перекрывает следующий блок.
- Правый клик по пустой части сообщения должен предложить копирование ID/details, а по тексту — не открывать это меню.
- В остановленном Claude и Codex набрать в floating terminal уникальную shell-команду без Enter, нажать History Resume и проверить: агент дошёл до READY, незапущенная команда не выполнилась, а повторный launch при живом агенте отклонён без `Ctrl+C`.
