# Fact: Log Compression Algorithms

Алгоритмы интеллектуальной очистки логов для экономии контекстного окна AI и читаемости при копировании. Не баг-фикс, а **продуктовая фича** — кнопка «Logs» в `ApiCallsList` / DevTools-копирование.

## 1. Grafana / Loki logs
Оптимизировано для дампа из веб-интерфейса Grafana.
- **Stderr-стрип**: удаляются строки-заголовки `stderr` (дублируют сообщение, идущее ниже).
- **Fields-секция**: вырезается блок метаданных `Fields` (hostname, service, source, instance) — для конкретной ошибки эта телеметрия избыточна.
- **Timestamp cleanup**: удаляются длинные ISO-даты в начале каждой строки, остаётся только текст сообщения.
- **Дедупликация**: повторяющиеся подряд одинаковые строки схлопываются в `×N`.

## 2. Browser Console / DevTools logs
Оптимизировано для копирования из DevTools.
- **Stacktrace strip**: удаляются строки вызова функций (`at Object.onClick (file.js:123)`), если они забивают текст — оставляется только error message.
- **Object truncation**: компактификация больших JSON-дампов `{...}` внутри строки лога.
- **File:line cleanup**: удаляются префиксы имён файлов в начале строк (DevTools пишет источник перед каждым log).

## 3. Общие правила
- **Результат**: после нажатия «Logs» объём текста в clipboard уменьшается на 60-90%.
- **Feedback toast**: исходный и финальный размер показываются юзеру («Сжато: 5000 → 800 символов») — без этой обратной связи юзер не понимает что произошло и не доверяет.

## Зачем
Один длинный лог из Grafana = 5-10K токенов в контекстном окне AI. После compression — 500-1000. Это разница между «AI прочитает весь лог + ещё код + ещё knowledge» и «AI прочитает только лог, остальное обрежется».
